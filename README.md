# Домашка.ПРО 4.1

Школьный помощник для 1–11 классов: решение и проверка заданий по тексту и фото, учебный диалог, калькуляторы, шпаргалки, тренировки, дневник и расписание.

## Обновление 4.1 — больше моделей без ключей

- **Пять отдельных демо:** Google Gemma 3 12B, Gemma 3n E4B, Gemma 2 9B, Meta Llama 3.2 3B и Mistral 7B v0.3. В чате **8 облачных вариантов + автовыбор**; Gemini/OpenRouter с собственными ключами остаются отдельно.
- Gemma 3/3n — **одно фото напрямую**, Gemma 2/Llama/Mistral — текст или OCR. Описания, ссылки на площадки и условные цветные оценки; старый выбор модели сохраняется.
- **Без внешней регистрации — в пределах анонимной квоты Hugging Face.** Она общая для демо, не отдельная на каждую модель; очередь и предварительный резерв GPU могут не позволить запустить даже короткий запрос. Новые демо выбираются вручную, без фоновых запросов, платного перехода и обхода лимитов.
- Отдельные браузерный/Python адаптеры, одно пяти­минутное ожидание, отмена, проверка полного SSE-ответа, безопасные ошибки и отсутствие скрытой подмены/повтора после серверного сбоя.

**Честно о проверке:** проверены публичные исходники, метаданные и GET-контракты API; генерация, реальная анонимная квота и фото на живых демо из среды разработки не проверены. Локальные проверки используют подставной транспорт. [Источники, контракты и ограничения](docs/PUBLIC_DEMOS.md) · [Отчёт QA 4.1](docs/QA_4.1.md).

- **Шпаргалки:** строгие фильтры всех классов и предметов, без автоматического глобального поиска. **1263 уникальные карточки (563 новые)**; минимум 25 всего в каждой из **106 изучаемых/подготовительных пар** набора. Общие карточки не клонируются. [Таблица покрытия и оговорки](REFERENCE_COVERAGE.md).
- Сохранены возможности 3.5: прямое Vision/явный OCR, ограничения iPhone HTML Viewer, голосовые подсказки, защищённый репетитор, выбор бесплатного шлюза в чате, описания моделей и Ollama/опциональный Python-мост. В этой версии 4.0 новые бесплатные шлюзы не добавлялись; расширение 4.1 описано выше.

**Важно:** √49 и подобные вопросы не подтверждают возраст. Аккаунты локальные, без автоматической синхронизации ПК/телефона; материалы и API-ключи не зашифрованы на диске. Пароли хешируются с солью, но это не родительский контроль ОС и не серверная аутентификация. [Настройка и все ограничения](USER_GUIDE.md#family).

## Просто пользоваться — без установки

**Открывать нужно [`Domashka_PRO.html`](Domashka_PRO.html).** Готовый файл теперь хранится прямо в репозитории, рядом с исходниками.

1. Откройте страницу файла по ссылке и нажмите **Download raw file / Скачать исходный файл**. Если GitHub не показывает содержимое из-за размера, скачивание всё равно доступно.
2. **На ПК:** сохраните файл и откройте его браузером. Node.js, Python и остальные исходники не нужны. Для облачного ИИ требуется интернет.
3. **На Android:** предпочтительна HTTPS-версия; локальное открытие зависит от браузера и файлового менеджера.
4. **На iPhone/iPad:** для HTML Viewer отдельно проверьте сохранность аккаунта после закрытия просмотрщика; фото выбирайте из галереи. Не все Viewer предоставляют нужную криптографию и хранилище. Надёжнее HTTPS в Safari; «Файлы» / Quick Look может не запускать локальный HTML.

**[Полная инструкция: ПК, Android, iPhone, нейросети, детский режим и резервные копии → USER_GUIDE.md](USER_GUIDE.md)**

Текстовая версия полной инструкции: [`USER_GUIDE.txt`](USER_GUIDE.txt). В переносимом ZIP есть `ПОЛНАЯ_ИНСТРУКЦИЯ.txt` и краткая `КАК_ЗАПУСТИТЬ.txt`.

Не открывайте двойным щелчком исходный `index.html`. Старый `workspace-…zip` — снимок **3.2**, а не актуальная версия. Если изменения ещё не объединены в `main`, готовый HTML нужно брать из ветки Pull Request.

### Постоянная ссылка для телефона

Добавлен необязательный workflow **Publish website (GitHub Pages)**. После объединения изменений в `main` владелец выбирает **Settings → Pages → Source: GitHub Actions**, затем вручную запускает workflow из `main`. Он публикует готовый HTML как главную страницу, а не исходный `index.html`.

[Пошаговая настройка HTTPS-сайта и обновлений](USER_GUIDE.md#pages). Хостинг **не включается автоматически**; адрес появляется после успешного deployment. Pages не запускает Python API и не синхронизирует данные между устройствами.

### Что хранится в репозитории

- `Domashka_PRO.html` — готовая клиентская версия для скачивания;
- `src/`, `backend/`, `shared/` — актуальные исходники;
- `USER_GUIDE.md` и `USER_GUIDE.txt` — полное пользовательское руководство, этот README — также команды разработки;
- `REFERENCE_COVERAGE.md` — воспроизводимая таблица покрытия классов и предметов;

`static/`, зависимости, пользовательские данные и `Domashka_PRO_Portable.zip` остаются вне Git. Исходники нужны для исправлений и дальнейшего развития; удалять их ради однофайлового запуска не требуется.

## Новое в 3.3

### Выбор нейросети

Нажмите кнопку настройки ИИ в шапке:

- **Бесплатный облачный ИИ без ключа:** автовыбор, Qwen 3.5 Omni, Pollinations или Qwen 2.5 VL. Это существующие публичные шлюзы, а не гарантированно доступная или локальная модель. Pollinations сам маршрутизирует запрос к модели.
- **OpenRouter:** свой API-ключ, обновляемый список бесплатных моделей и `openrouter/free` для автоматического выбора. Текстовые модели используют отдельное распознавание фото.
- **Gemini:** свой ключ Google AI Studio, конкретная модель или явный автовыбор Flash → Flash-Lite. Доступность бесплатной квоты и возможный биллинг определяются аккаунтом и правилами Google.
- **Ollama / свой API:** прямой OpenAI-совместимый API или включаемый владельцем Python-мост с фиксированным адресом; [пошаговая инструкция](USER_GUIDE.md#ollama).

Конкретная выбранная модель больше **не заменяется незаметно** другой при ошибке. Отсутствующий ключ не переключает приложение на другого провайдера. Только явно выбранный автовыбор допускает резервирование. Проверка связи проверяет ответ выбранного сервиса (облачного или своего Ollama), а не локальный запасной ответ.

### Детский режим с родительским паролем

1. Выберите класс ребёнка и настройте нейросеть.
2. Нажмите кнопку со щитом/замком в шапке.
3. Задайте и подтвердите родительский пароль (8–128 символов).
4. Включите режим. Для выхода или смены пароля потребуется действующий пароль.

В этом режиме доступны **репетитор, семья, дневник и справочник**. Обычные чаты скрываются, но не удаляются. Проверки-чистовики, калькуляторы решений, генераторы ИИ-тестов, импорт/экспорт общей истории и изменение настроек ИИ закрыты. Новые учебные диалоги сохраняются отдельно по признаку режима.

Репетитор получает возрастные инструкции: один шаг, короткая подсказка и один вопрос за раз; без готового ответа, сочинения или кода решения. Политика применяется к первому запросу, дальнейшему диалогу, запросам через Python-сервер и локальному запасному ответу. Точное решение/бейдж с корнями не выводится. Контекст длинного диалога ограничен исходным заданием и последними обменами, чтобы уменьшить объём запросов. В диалогах с Vision все исходные изображения передаются и в продолжении разговора; признак Vision хранится явно, независимо от текста ответа модели.

**Границы защиты:** это локальная защита интерфейса и учебная политика, а не полноценный родительский контроль. Новый браузер/профиль, очистка данных, инструменты разработчика или изменение HTML могут обойти её. Состояние сайта не переносится автоматически в скачанный HTML. Нейросеть может нарушить инструкции — гарантировать отсутствие готовых ответов нельзя. Для строгой защиты нужны серверные аккаунты, авторизация и серверная политика, не управляемая клиентом.

Пароль не отправляется в сеть и не хранится открытым текстом: используется PBKDF2-SHA256, случайная соль и 310 000 итераций. Есть задержка после повторных неверных попыток. Настройка требует постоянного хранилища браузера и Web Crypto (HTTPS либо локальный HTML в современном браузере). Восстановления забытого пароля нет.

## Разработчикам: запуск и сборка

Нужны **Node.js 20+** и **Python 3.11+**. Для одного готового HTML они не требуются.

```bash
npm ci
python3 -m venv .venv
# Linux/macOS:
.venv/bin/pip install -r requirements.txt
# Windows: .venv\Scripts\python -m pip install -r requirements.txt

# Собрать сайт и автономные HTML/ZIP:
npm run build:standalone

# Запустить сайт с серверными ИИ/OCR-запросами:
.venv/bin/python server.py
```

Откройте `http://localhost:8000`. На Windows используйте `.venv\Scripts\python server.py`; при необходимости запустите `npm run build`, затем `python build_standalone.py`.

Для разработки в другом терминале:

```bash
npm run dev
```

Vite слушает `0.0.0.0:5173`, относительные `/api/*` проксируются на Python `:8000`. Браузер не обращается к адресу серверного localhost напрямую. В режиме прямого подключения к своему API браузер использует заданный пользователем адрес. В режиме Python-моста — только относительный `/api/ai-generate`, а upstream задаёт администратор через `DOMASHKA_ENABLE_OLLAMA_PROXY=1` и необязательный `DOMASHKA_OLLAMA_URL`. Не открывайте сервер без авторизации в публичную сеть; проверка Origin/Host не является авторизацией.

Артефакты сборки:

- `static/` — сайт для Python-сервера;
- `Domashka_PRO.html` — отслеживаемый Git готовый HTML со встроенными JS/CSS/шрифтами KaTeX; `static/Domashka_PRO.html` — его копия для серверного скачивания;
- `Domashka_PRO_Portable.zip` — HTML, краткая и полная инструкции, ярлыки запуска. Полная инструкция берётся из `USER_GUIDE.md`, чтобы не расходиться с документацией.

На совместимом настольном браузере скачанный HTML открывается напрямую через `file://`. На Android это зависит от способа открытия; на iPhone/iPad рекомендуется HTTPS. Облачный ИИ и часть OCR/PDF-функций требуют интернета. Калькуляторы на JS, справочник, дневник и история работают локально. Режим с локальным ИИ требует отдельно установленной и запущенной модели; распознавание фото может использовать облако.

После изменения исходников или версии **пересоберите и включите новый `Domashka_PRO.html` в тот же коммит**. Workflow **Tests and standalone build** запускает тесты, повторяет сборку и проверяет `git diff --exit-code -- Domashka_PRO.html`. Сгенерированный файл помечен в `.gitattributes`, чтобы GitHub сворачивал его большой diff, но он остаётся доступен для скачивания.

Подготовка файлов для статического HTTPS-хостинга (не включает хостинг сама по себе):

```bash
python3 scripts/prepare_pages.py
# Результат: .cache/pages-site/index.html, Domashka_PRO.html, .nojekyll
```

Полный сценарий публикации и повторного запуска описан в [руководстве](USER_GUIDE.md#pages).

## Тесты

```bash
npm test
.venv/bin/python -m unittest discover -s tests -p 'test_*.py' -v
npm audit
```

Тесты покрывают пароль и сохранение режима, защиту всех AI-путей, выбор провайдера/модели, сетевые таймауты/отмену, фотографии и историю, очистку HTML, счётчики и математические решатели. Внешние ИИ/OCR-сервисы подменяются: тесты не расходуют квоты и не утверждают, что публичные шлюзы сейчас доступны. Регрессии включают реальные loopback-HTTP проверки мостика с подставным Ollama, нативные image-payloads, блокировку постороннего Origin, мобильные защитные ветки и жизненный цикл подставного Speech API. Браузерные проверки выполняются в Chromium с тестовыми ответами: это не проверка настоящего HTML Viewer, iPhone, микрофона или доступности публичных ИИ.

## Данные и безопасность

- Текущий интерфейс сохраняет чаты и фото в IndexedDB, настройки/дневник — в localStorage; при ограничениях хранения используется урезанная резервная история. SQLite обслуживает отдельные серверные маршруты и **не синхронизируется автоматически** с браузерной историей.
- API-ключи хранятся в браузере **не зашифрованными** и передаются выбранному провайдеру, а в серверном режиме также вашему серверу. Родительский пароль не является ключом шифрования данных.
- Облачные ИИ/OCR-провайдеры получают текст и фото. Не загружайте личные данные детей и не встраивайте общие секретные ключи в HTML.
- Markdown очищается от опасного HTML; математический Python-парсер ограничен разрешённой грамматикой.
- Python-сервер предназначен для локального/доверенного использования: это не готовая многопользовательская production-система. Для публичного размещения нужны HTTPS, авторизация, квоты, изоляция вычислений и политика обработки данных.
