# Вход без почты и 10 резервных кодов

## Для пользователя

Облачный родительский аккаунт создаётся по **уникальному логину и паролю**, без настоящего email, телефона, SMS или SMTP. Логин — 3–24 латинских буквы, цифры, `-` или `_`, без учёта регистра; имя и аватар выбираются отдельно. Пароль — минимум 8 символов, максимум 72 байта UTF-8 (до 72 латинских символов; кириллица/эмодзи занимают больше байт).

После регистрации **все 10 резервных кодов показаны сразу**. Можно скачать TXT или скопировать список. Сохраните его отдельно, например в менеджере паролей. Кнопка продолжения доступна после явного подтверждения сохранения; нажатие «Скачать» само по себе не доказывает, что файл сохранён. На iPhone проверьте «Файлы → Загрузки»/место, выбранное Safari. Физический iPhone этим обновлением не проверен.

При забытом пароле: **«Забыли пароль?» → логин → один полный неиспользованный код → новый пароль дважды → антиспам**. Один успешный сброс использует один код. Оставшиеся девять (затем восемь и т. д.) продолжают действовать; новый набор автоматически не выдаётся. Зачёркивайте использованные коды. Старые сеансы требуют нового входа.

«Семья → Резервные коды восстановления» показывает **только количество оставшихся**, не прежние секреты. После подтверждения текущего пароля можно перевыпустить все 10 кодов. Это отменяет **весь старый набор**, включая неиспользованные коды. Новый список снова показывается целиком и требует сохранения. Между перевыпусками — минимум минута. Обычная смена пароля сохраняет неиспользованные коды.

**Потеряли ответ сервера?** Не повторяйте сброс автоматически и не тратьте следующий код сразу. Сначала попробуйте новый пароль: операция могла завершиться до обрыва связи. Если ответ регистрации/перевыпуска с кодами потерян, войдите с паролем и перевыпустите набор через минуту. Сервер не может повторно показать первоначальные коды.

Без пароля и действительного кода самостоятельного восстановления нет. Логин, имя, математический вопрос и просьба в поддержке сами по себе не доказывают владение аккаунтом. Не присылайте коды/пароль в Arena, помощнику или другим людям. TXT-файл содержит секреты и не зашифрован приложением.

Ребёнку коды родителя **не передают**. Родитель создаёт детский полный логин/пароль и сбрасывает пароль ребёнка через семейный кабинет. Для всех новых облачных паролей, включая детские, действует одна граница: минимум 8 символов и максимум 72 байта UTF-8; её проверяют клиент и сервер. Локальные пароли автономного HTML не меняются. Старые email-аккаунты, если они были созданы ранее, сохраняются: вход по прежнему адресу и перевыпуск кодов после проверки пароля поддерживаются. Новая форма не создаёт email-аккаунты и не отправляет письма.

Автономный `Domashka_PRO.html`/HTML Viewer остаётся локальным; облачная схема не превращает его данные или пароли в серверные. Для облака нужен опубликованный HTTPS-сайт.

## Устройство и границы безопасности

- Supabase Auth продолжает хешировать/проверять пароли и выдавать сеансы. Приложение не хранит открытый пароль и не реализует свою таблицу парольных хешей.
- Родительский логин сопоставляется с техническим `login@parents.domashka.invalid`; ребёнок — с `login.familycode@children.domashka.invalid`. Это зарезервированные недоставляемые адреса, не почтовые ящики. Владение настоящей почтой такая схема не подтверждает.
- Нативная публичная регистрация Supabase остаётся **выключенной** (`disable_signup=true`); email/password-провайдер включён для парольного входа. Защищённая `account-access` создаёт только родителя с проверенным сервером логином. Служебный `email_confirm: true` означает готовность технической идентичности, не подтверждённый email человека.
- Код: независимые 16 байт Web Crypto CSPRNG (128 бит), 32 hex-символа в четырёх группах. Сервер сохраняет только SHA-256 с разделителем назначения. Для высокоэнтропийных случайных кодов медленный парольный KDF не требуется. В `backup_codes` нет исходного кода, обратимого шифротекста или пароля.
- Кодовые таблицы/разрешения/квитанции находятся в **неэкспонированной** `domashka_private`; `anon`/`authenticated` не имеют прямого доступа. Публичный RPC статуса доступен только действующему родителю и возвращает счётчик.
- Регистрация/восстановление проверяют точный Origin, размер/структуру запроса, Turnstile success + **точный hostname + action `domashka-auth`**, затем серверное разрешение. Нет секрета CAPTCHA — отказ 503. Стандартные тестовые Turnstile secrets в опубликованной функции отклоняются. CORS и IP не считаются доказательством личности.
- Квоты попыток атомарны в PostgreSQL: регистрация 5/логин/час, 10/IP/час, 120/проект/час, 500/проект/сутки; восстановление 10/логин/час, 30/IP/час, 300/проект/час, 1000/проект/сутки. В журнале только серверно-солёные хеши IP/логина, без паролей/кодов; старые попытки удаляются при следующем запросе после 24 часов. IP — дополнительное ограничение, не единственное: прокси-заголовок может отсутствовать/быть недоверенным.
- Разрешение на восстановление живёт 2 минуты, привязано к пользователю, коду и эпохе пароля. Проверка разрешения, одноразовое использование кода и изменение пароля входят **в одну транзакцию Auth**. Повтор/два заранее выданных разрешения на один код не приводят к двум сбросам; отклонённая транзакция не расходует код. При гонке разных кодов проигравший сохраняется.
- У GoTrue admin API пароль и app_metadata могут обновляться **разными SQL-операциями в одной транзакции**. Приватная квитанция `pg_current_xact_id()` связывает поздний ticket с именно этим изменением пароля. Квитанция из другой транзакции непригодна. Регистрация использует заранее разрешённый UUID, потому что GoTrue записывает app_metadata и `email_confirm` после INSERT. Тот же контракт исправлен для создания/сброса ребёнка; нельзя тестировать только вымышленный единый INSERT/UPDATE.
- Перевыпуск требует действующего исходного сеанса и **отдельной повторной проверки текущего пароля**; БД перепроверяет обе сессии, роль, блокировку и свежесть проверочной сессии. Старые коды заменяются атомарно. Сервисный ключ не попадает в браузер.
- Ответы `no-store`, входящие тела/секреты не логируются; коды не входят в URL, учебный outbox, IndexedDB, localStorage, JSON-экспорт учебных данных или автоматический контекст ИИ. Отформатированные коды дополнительно маскируются в справочном помощнике. Это не защита от вредоносного расширения браузера или человека с доступом к скачанному TXT.

## Настройка владельцем

Сначала все миграции (старые не повторять), затем `account-access` и обновлённая `family-admin`. В Auth оставить signup закрытым, включить email/password для технических идентичностей, minimum password length 8 и требование текущего пароля при самостоятельной смене. Anonymous/phone sign-ins не нужны. **Не включать почтовые уведомления о смене пароля/адреса для этой схемы.**

Для Turnstile один реальный виджет с точным hostname сайта:
1. Public site key → `DOMASHKA_TURNSTILE_SITE_KEY` при сборке HTML.
2. Secret key → Supabase Auth CAPTCHA (провайдер Turnstile) для обычного входа/повторной проверки пароля.
3. Тот же secret key → **Edge Secrets `DOMASHKA_TURNSTILE_SECRET_KEY`** для публичных `register`/`recover` в `account-access`. Одной настройки Auth CAPTCHA здесь недостаточно: admin API не проверяет CAPTCHA за Edge Function.
4. Пересобрать и вручную загрузить новый Cloudflare ZIP. Ручной upload не обновляется сам от изменения GitHub. Настоящий секрет вводится в панели владельца, не в чат/Git/HTML.

SMTP, почтовые шаблоны и покупка почтового домена больше не являются условиями новой регистрации. Антиспам, серверные ограничения и приёмочный прогон по-прежнему обязательны. См. [текущий запуск](CLOUD_LAUNCH.md) и [общую установку](CLOUD_SETUP.md).

## Проверки

`tests/usernameRecovery.test.jsx`: регистрация без email; все десять видны сразу; явное подтверждение сохранения; TXT; восстановление расходует один; остаток и перевыпуск; отсутствие кодов в browser storage; маскирование в помощнике.

`tests/accountAccessServer.test.js`: исполняется настоящий Edge handler с подставными Auth/HTTP. Проверены 10 случайных кодов/хеши, серверно назначаемый UUID/роль, отсутствующая конфигурация/тестовый secret, Origin/JSON/размер, CAPTCHA hostname/action, квоты, отказ/таймаут без повтора, код и перевыпуск после повторного пароля.

`tests/familyAdminServer.test.js` и `tests/cloudRuntime.test.js`: единые границы новых облачных паролей на клиенте/сервере (включая UTF-8), заранее назначенный UUID ребёнка, повторная проверка родителя и передача текущего пароля в Auth при самостоятельной смене.

`scripts/test_username_sql.mjs` вызывается из `npm run test:cloud`: реальные миграции PostgreSQL/PGlite, права ролей, 10 одноразовых использований, двойной ticket/гонка эпох, rollback пароля/кода, чужой код/сеанс, блокировка, перевыпуск/старые коды, статус и реальные порядки SQL-вызовов GoTrue. Auth/Storage-сервисы здесь — фикстуры, не живой запрос к провайдеру. Случайные fixture-значения тестов не являются пользовательскими кодами.

Успех тестов не означает, что уже настроен Turnstile, обновлён опубликованный сайт или проверены реальные устройства.
