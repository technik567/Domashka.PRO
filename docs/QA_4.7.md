# Проверки 4.7 — ответ или поиск без обязательного JSON-планировщика

## Результат и границы

- Включённый интернет **больше не требует отдельной генерации JSON-плана для каждого вопроса**. Первый вызов либо отвечает, либо просит источники. Обычный ответ используется сразу; teacher/reasoning/graphics/photo-настройки сохранены. При отсутствии поиска добавляется явное уведомление.
- Настоящий поиск запускается только после строгой проверки ограниченной команды и всех коротких фраз. Неверная команда, личные данные, старый `search:false` и повторная команда в следующих этапах не запускают поиск или восстановительную генерацию.
- Успешный поиск не теряется, если модель после него отказала: показываются **только настоящие выдержки и ссылки, не ответ выбранной модели и не готовое решение**. Без повторов, замены модели и проверок. Отмена, отказ первой генерации и ошибка самого поиска не становятся таким результатом.
- **Сквозной живой поиск Pollinations не подтверждён.** Первый контроль остановился на неподдерживаемом ответе; отдельная диагностика установила `finish_reason:tool_calls`. После добавления `tool_choice:none` текст получен, но команда отклонена как `search-action-invalid`; Tavily не вызывался. Неуспешные jobs не скрыты и не перезапускались ради зелёного статуса.
- Скриншот Gemma показывает внешнюю GPU-квоту; Qwen — неизвестный upstream-отказ. Удаление лишнего прохода не восстанавливает уже потраченную квоту и не доказывает исправность внешнего backend. Причины этих двух отказов не объявлены одной проблемой с поиском.
- Физический iPhone/HTML Viewer, текущий облачный сеанс пользователя, живой поиск через Supabase, восстановление всех 13 вариантов не проверены. Браузерные фикстуры не выдаются за эти сценарии.

## Живые ограниченные проверки — три запроса модели всего

Каждый запуск отдельный и явный. Только вымышленный публичный вопрос о числе планет/NASA; без пользовательской переписки/фото/учётных записей/ключей/платежей. Никаких HF-запросов, повторов отказа внутри приложения, смены IP или обхода квот. Во всех трёх фактических запусках **поисковых POST — 0**, генераций — по одной. Не выполнялся эксперимент с чужими аккаунтами или снятием CAPTCHA.

Третий проверял **изменённый транспорт**, а не повторял неизменённый сбой. Различие результатов не доказывает, что один параметр устраняет все внешние ошибки. Неизвестно, какой именно неверный текст был в последней команде: raw output намеренно не журналируется. Проверка не ослаблена, подсказки не восстанавливаются догадкой.

В [зафиксированном legacy-origin](https://github.com/pollinations/pollinations/blob/bf4c219e3581821df582930b925533d4fcd9bec5/text.pollinations.ai/cloudflare-cache/src/origin.js) `readParams` передаёт `tool_choice` upstream. Клиент и Python теперь явно запрещают native tools; текстовая команда `domashka-search` остаётся единственным действием приложения. Неподдерживаемые tool/function окончания всё ещё отклоняются. Имена/аргументы tools, private reasoning и raw error не попадают в ответ, callbacks, историю и отчёт.

Исторические два коротких ответа Pollinations / отказы Qwen и старый план→тайм-аут относятся к **4.6**, не являются приёмкой 4.7: [QA 4.6](QA_4.6.md).

HTTP Auth/Storage/AI/search в локальном прогоне подставной; PGlite исполняет реальные SQL. Мобильные тёмные скриншоты обычного ответа и sources-only просмотрены. Отказ запуска Chromium из-за отсутствующей `libnspr4.so` устранён установкой библиотек окружения (`/tmp/al2023/lib`), не ослаблением браузерных защит. После изменения текста подсказки синхронизировано ожидаемое сообщение UI-теста; полный прогон повторён успешно. Сквозной **живой** результат выше остаётся failure независимо от этой таблицы.

Проверено:

- `npm test`: обычный ответ с Internet auto для Pollinations, Qwen 3.5 и Gemma через реальные клиентские адаптеры с подставным HTTP; 1/2/3 прохода без поиска, 2/3/4 при запросе источников. Правила учителя/репетитора, глубина, графики, фото и no-switch сохранены.
- Проверка всей команды до сети: лимиты/типы/CRLF/dedup, secret/email/phone/code, отсутствие full chat/photo в поиске, неверный/пустой/legacy false план без восстановления, запрет рекурсивного поиска.
- Ошибки начальной модели, реального поискового этапа и после успешного поиска различаются. `sourcesOnly` не содержит raw error, не запускает review/retry, сохраняет только реальные данные; Stop не публикует поздний fallback.
- Отображение выдержек: Markdown/HTML/images/KaTeX/GFM-autolink не исполняются. В первой попытке backslash-экранирование не мешало GFM создавать URL; заменено на numeric entities. Отдельная регрессия защищает этот случай.
- Pollinations: штатный endpoint/model/stream/бюджет, `tool_choice:none`, отсутствие auth/cookies/payment, fixed diagnostics, complete-only, size limits, отмена, отказ native tools, partial/402/429. Python применяет тот же запрет tools.
- Опциональные probes: не делают запросов без флага; bounded real workflow/direct search; ordinary answer ≠ успешный поиск; initial/search отказ; отдельный sources-only; Node guest cleanup; отчёты без запроса/ответа/секретов. Никаких подмен hosted identity.
- PGlite SQL/fixtures: аккаунты, независимые одноразовые коды, детские права, приватные работы/фото, outbox, квоты и неизменность установленных миграций.
- Собранный HTML под CSP, Chromium 320/390 px: no mandatory planner, поиск/проверка/отмена, malformed/native action, source-only без активной инъекции, Gemma обычным ответом в одной генерации, сохранение ручного Qwen, черновиков/фото/истории/тем/10 кодов. HTTP подставной, SQL реальный в PGlite; не физический телефон.

## Бюджеты и доступ

Без нового ключа/провайдера: Pollinations 120 с, Qwen/Auto 300 с, весь workflow 480 с; direct search 22 с, cloud 35 с, Edge 30 с. До четырёх логических генераций, двух поисков и двух проверок. Настройки глубины реально влияют на отдельные проходы, но не гарантируют правильность. Stop отменяет ожидание/последующие действия, не обещает возврат чужой квоты.

`probe_search_workflow.mjs --run-live` допускает максимум 2 Pollinations + 1 keyless Tavily, 270 с. Без флага — exit 2 и **0 запросов**. Отдельный `--inspect-response` — максимум один Pollinations, без поиска. CI inputs `search_workflow` / `pollinations_diagnostic` выключены по умолчанию; PR/main/check не расходуют модельную квоту. Отчёты сохраняют только фиксированные коды, этапы, статусы, время headers/счётчики и домены источников. Успех ordinary answer или только источники не помечаются `verified` для полного поискового цикла.
