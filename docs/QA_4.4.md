## Воспроизведение

```sh
npm ci
npm test
npm run check:reference
npm run test:cloud
npm run build:standalone
.venv/bin/python -m unittest discover -s tests -p 'test_*.py' -v
# Deno 2 с существующим frozen lock:
deno check --no-config --node-modules-dir=none --frozen --lock=supabase/functions/deno.lock supabase/functions/family-admin/index.ts supabase/functions/web-search/index.ts supabase/functions/account-access/index.ts
# Playwright/Chromium из среды QA (не нужен пользователю приложения):
node scripts/test_cloud_browser.mjs
node scripts/test_features_browser.mjs
node scripts/test_username_browser.mjs
```

Браузерные сценарии используют настоящий собранный HTML, строгий CSP, настоящий SQL в PGlite и **явно подставные HTTP Auth/Storage/ИИ/поиск**. Это не работающий live backend. Пароли/коды/ключи в фикстурах вымышленные. Снимки/логи находятся в игнорируемой `.cache`, не в поставке.

## Отдельная добровольная сетевая проверка

Обычные unit/CI/browser тесты **не отправляют** живые запросы провайдерам. В существующем workflow `check.yml` добавлен отдельный `public_smoke=false` по умолчанию. Только явный запуск с `true` разрешает `scripts/probe_public_routes.mjs`: короткое вымышленное `2 + 2`, официальный Qwen3 adapter и один keyless-запрос Tavily. Никаких ключей/secrets, реальных заданий или платных сервисов; при отказе общей площадки остальные модели не перебираются. Общий предел job 8 минут, отчёт `public-route-smoke` отдельно от локальной регрессии. Даже успешный Node-запрос не доказывает browser CORS/доступ с телефона. Наличие такого скрипта само по себе не является успешным live-тестом.

## Что не проверено и не сделано

- Не выполнялось развёртывание в Supabase/Cloudflare: подключение Supabase выключено, Git Builds не настраивался, новый Worker не создавался. Существующую `web-search` нужно обновить отдельно; SQL не повторять.
- Прямые безличные POST к `qwen-qwen3-demo.hf.space` и `api.tavily.com` не прошли сетевое соединение из sandbox (HTTP 000/TLS failure). Доступные публичные GET-исходники/metadata и мок-тесты **не доказывают** успешный анонимный inference, keyless-квоту или CORS на пользовательском устройстве. Новые Qwen3 названы экспериментальными.
- Не проверены физический iPhone, сторонний HTML Viewer, живые камера/диктовка, реальные парольные операции и синхронизация двух физических устройств. Браузерные размеры 320/390 px не заменяют эти проверки.
- Дополнительные проходы той же модели не гарантируют правильность, поиск отдаёт выдержки, не полные страницы. Арифметическая проверка намеренно узкая. Нет бесконечных циклов, обхода квот, встроенных личных ключей или автоматического платного переключения.
- Текущая ветка не объединена, release/tag не создавались. ZIP/HTML не являются публикацией действующего сайта.
