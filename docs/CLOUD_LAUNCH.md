## Что пока мешает открытой регистрации

На последнем чтении настроек:
- **Turnstile не настроен**: Auth CAPTCHA выключена, Edge secret `DOMASHKA_TURNSTILE_SECRET_KEY` отсутствует, в собранном ZIP пока нет public site key. `account-access` намеренно отказывает публичной регистрации/восстановлению без секрета; новый клиент не отправляет эти формы без site key.
- Auth minimum password length пока **6**, требование текущего пароля выключено. Новый путь регистрации/восстановления уже проверяет минимум 8 и предел 72 UTF-8 байта, но глобальные параметры Auth нужно довести до безопасных значений отдельно.
- Старый опубликованный клиент ещё требует почту — его нужно обновить после получения site key.
- **TAVILY_API_KEY** отсутствует на последнем чтении секретов; полный поиск не подтверждён. Это отдельная настройка, не условие паролей.

`disable_signup=true` теперь **нужно оставить и после запуска**. Это запрет прямого `auth.signUp`, а не выключатель защищённой регистрации через `account-access`. `external_email_enabled=true` нужен для технических парольных идентичностей; `mailer_autoconfirm=false` можно оставить. Письма для регистрации/восстановления не отправляются. Почтовые уведомления о смене пароля/адреса оставить выключенными. Не отключать защиты ради демонстрации.

## 1. Настроить Turnstile в своей панели Cloudflare

1. Открыть **Turnstile → Add widget** (названия могут меняться). Название, например «Domashka.PRO». Тип **Managed**.
2. В hostname добавить **`gentle-fog-7c3b.jr-polyakoff.workers.dev`**, без `https://` и пути. Не разрешать все домены.
3. Сохранить виджет. **Site key — публичный**: его можно сообщить агенту для пересборки ZIP. **Secret key — секретный**: вводить только в указанные ниже настройки, не в чат/Git/HTML.
4. В Supabase Authentication CAPTCHA settings выбрать **Turnstile**, включить защиту и сохранить secret key — для обычного входа и повторной проверки пароля.
5. В [Edge Functions / Secrets](https://supabase.com/dashboard/project/zgfjfngcwtupqyirwfha/functions/secrets) добавить **`DOMASHKA_TURNSTILE_SECRET_KEY`**, значение — тот же secret key. Эта отдельная проверка защищает `account-access`; admin API не выполняет её сам.
6. В Auth установить minimum password length **8** и **Require current password for password changes**. Прямую регистрацию **не включать**. Не включать email-уведомления для технических `.invalid`-адресов.

Интеграция Arena с Cloudflare в этом сеансе не доступна через коннектор; настройки виджета делает владелец в панели. Секреты вводить самостоятельно, не пересылать. Для существующего Supabase нужны не новые учётные данные, а эти настройки.

## 2. Пересобрать и обновить существующий Workers-сайт

Публичные переменные сборки:

```text
DOMASHKA_SUPABASE_URL=https://zgfjfngcwtupqyirwfha.supabase.co
DOMASHKA_SUPABASE_PUBLISHABLE_KEY=sb_publishable_LNQuFvv9MW97eqMjPIdp1g_p0qnlL9M
DOMASHKA_SITE_URL=auto
DOMASHKA_TURNSTILE_SITE_KEY=публичный_site_key_вашего_виджета
```

Последняя строка — обозначение места для настоящего site key, не рабочее значение. Для пересборки агенту достаточно **этого публичного ключа**, secret key ему не нужен. Publishable key Supabase намеренно публичен и не даёт административного доступа.

```sh
npm ci
npm run build:standalone
python3 scripts/prepare_cloud.py --zip Domashka_PRO_Cloudflare.zip
```

Затем в **существующем** Cloudflare Workers-проекте открыть загрузку новой версии статических assets. Загрузить содержимое ZIP: в корне должны оказаться `index.html` и `_headers`, без внешней папки. Если интерфейс Worker принимает только папку, распаковать ZIP и загрузить её содержимое. Не загружать корень репозитория, `.env`, SQL/Edge-код или `.git`.

- **`Domashka_PRO_Cloudflare.zip`** — облачный сайт; **`Domashka_PRO_Portable.zip`** — отдельная локальная программа. Не перепутать.
- `siteUrl:auto` определяет origin браузера, но не настраивает Auth/Edge/Turnstile. Для этого проекта Auth/Origins уже записаны правильно.
- Старый pinned ZIP остаётся старой версией. Брать новый файл из текущей ветки/нового коммита, а не прежнюю ссылку с фиксированным hash.
- После загрузки проверить, что на реальном сайте есть **«Логин родителя»**, **«Восстановить по коду»**, предупреждение о десяти кодах и настоящий Turnstile. Кэш-заголовки no-store не заменяют успешную загрузку нового файла.
- Внутренний `/Domashka_PRO.html` по-прежнему автономный и без cloud config. На iPhone облако открывать в Safari; HTML Viewer — локальный режим.
