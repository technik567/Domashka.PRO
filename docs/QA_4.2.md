## Что именно проверяется

- JavaScript / Vitest: прежние регрессии AI, фото, моделей, семейных аккаунтов, интерфейса, справочника и расписания; короткие ответы/награды; CAS и очередь; привязка запросов к UID и сеансу, замораживание старого редактора, безопасный перенос.
- Python / unittest: прежние HTTP/Ollama/фото/SSE и упаковка; облачный builder принимает только публичную конфигурацию, не изменяет скачиваемый HTML, не выдаёт GitHub Pages за сайт с облачным входом.
- `test_cloud_sql.mjs`: **100 assertions**, реальные шесть миграций PostgreSQL на PGlite. RLS/права/семьи/версии/карточки/импорт/отзыв сеансов/admin tickets/ограничения закрытых фото. Auth/Storage-таблицы и JWT claims — **фикстуры**, это не запуск Supabase.
- `flashcard_bank.mjs --check`: **1700 карточек / 4881 короткая проверка / 0 без проверки**, соответствие банка исходникам. Отдельные примеры проверяют одинаковую нормализацию чисел браузером и SQL.
- `check:reference`: **1263 уникальные справочные карточки, 563 добавленные ранее; 106 пар «класс — предмет» с минимум 25**. Не путать справочные статьи с извлечёнными из них учебными карточками.
- Deno: изолированный type-check Edge Function с lockfile. Он не доказывает работу функции в размещённой среде.

## Браузерная интеграция

`node scripts/test_cloud_browser.mjs` использует **собранный HTML**, публичный builder и его настоящие CSP-заголовки. Chromium запускает независимые desktop/mobile browser contexts. Supabase SDK выполняет настоящие клиентские вызовы, но HTTP Auth/Storage перехватывается; RPC исполняются на реальном PGlite с миграциями и RLS. Запросы сериализованы, так что это **не проверка конкурирующих транзакций PostgreSQL на разных соединениях**.

Сценарии:

1. Один детский логин открывается в двух независимых хранилищах браузера.
2. Дневник переносится после сохранения и явного обновления, не подменяет открытый редактор в фоне.
3. При недоступном mock-backend очередь остаётся в IndexedDB, включая неуспешную повторную загрузку кабинета.
4. После конкурирующих изменений сохраняются обе версии; выбор облачной версии сначала убирает старый редактор, ждёт сохранения кэша и позволяет перезагрузку.
5. Вторая вкладка того же origin блокируется, не подменяется локальной семьёй.
6. Неверный короткий ответ — 0 XP; верный — +4; повтор стопки не выдаёт ещё +4.
7. Родитель назначает работу, ребёнок сохраняет черновик и отправляет тестовое фото; родитель явно подтверждает новую версию, получает фото и проверяет ответ. Обновления не стирают текст формы.
8. Явный перенос сохраняет private-ссылку вместо base64 в документе; ребёнок не может превратить старые XP в новые подтверждённые.
9. Автономный HTML не открывает облачную регистрацию; отдельно проверяется `file://`, отсутствие native `randomUUID`, сохранение восьми бесплатных моделей плюс Auto и локальная проверка ответа.
10. Ширины 390 px (облако) и 320 px (локальный файл), отсутствие горизонтального переполнения и необработанных ошибок страницы. Незапланированные внешние запросы запрещены.

Браузерный прогон обнаружил лишние конфликты одинаковых начальных настроек двух устройств. Исправление подтверждает **только точно одинаковое текущее значение**; новый ввод во время запроса не теряется и различающиеся версии по-прежнему требуют выбора. Добавлены отдельные unit-регрессии. Также исправлена повторная активация кнопки перезагрузки после выбора облачной версии и завершения записи IndexedDB.

## Воспроизведение

Node.js **22+**, Python **3.11+**, Deno 2. Зависимости Python устанавливаются из `requirements.txt` в `.venv`.

```sh
npm ci
npm test
npm run test:cloud
npm run check:reference
npm run build:standalone
.venv/bin/python -m unittest discover -s tests -p 'test_*.py' -v
deno check --no-config --node-modules-dir=none --frozen --lock=supabase/functions/deno.lock supabase/functions/family-admin/index.ts
```

Необязательный браузерный прогон: установите `playwright-core` отдельно (`npm --prefix .cache/browser install --no-audit --no-fund playwright-core`), укажите путь к совместимому Chromium через `CHROMIUM_PATH` и выполните `node scripts/test_cloud_browser.mjs`. Можно задать `PLAYWRIGHT_MODULE` как путь к `playwright-core/index.mjs`. Скрипт сам запускает/закрывает временный HTTP-сервер и не публикует данные. Системные библиотеки Chromium должны быть установлены. В Arena использован Chromium 153; в этой минимальной среде дополнительно потребовались библиотеки из комплекта `@sparticuz/chromium`. Это инструменты в `.cache`, не зависимости выпуска.

Готовый HTML и `USER_GUIDE.txt` отслеживаются в Git. ZIP собирается из HTML, TXT/MD-руководства, короткой инструкции, материалов облачной настройки/QA/публичных моделей, таблицы справочника и ярлыков запуска; остаётся генерируемым артефактом. Сравнение повторных ZIP выполняется по **содержимому файлов**, не по меткам времени архива. Предупреждение Vite о размере единого JS-пакета ожидаемо для переносимого HTML.

## Реальный Supabase: выполнена начальная установка

После локального прогона владелец отдельно подтвердил создание Free-проекта. В настоящем проекте `zgfjfngcwtupqyirwfha` установлены шесть миграций и банк 1700/4881; проверены RLS/GRANT metadata, закрытый bucket, отсутствие пользователей и удаление временного HTTP-компонента установки. Auth/DB/REST/Storage вернули healthy. `family-admin` развёрнута как версия 1 / ACTIVE, но её пользовательские операции пока не запускались: Origin сайта ещё не задан.

Регистрация закрыта, email confirmation включён, SMTP/Turnstile/реальный Site URL не настроены. Это **ограниченная проверка схемы и состояния служб**, не живой пользовательский сценарий. Исходники БД взяты из коммита `16f1906cb20f54976b3098b1a89e2bd8518f75b8` с SHA-256-проверкой; первая ошибка служебной SQL-обёртки полностью откатилась, состояние пустой базы проверено перед исправленной установкой. Неполных миграций не оставлено. [Текущий статус и шаги владельцу](CLOUD_LAUNCH.md).

## Что НЕ проверено и НЕ опубликовано

- Пользовательский вход GoTrue, refresh/recovery/confirmation через реальную почту, SMTP-квоты/доставляемость и Turnstile у провайдера.
- Вызов размещённой Edge Function с настоящими admin keys, работа клиентского Storage API и поведение конкурирующих транзакций многопользовательского сервера.
- Реальные ПК + телефон одновременно, Safari/WebKit, физический iPhone, HTML Viewer, разрешения камеры и диктовка настоящим микрофоном. Мобильный viewport Chromium этого не подтверждает.
- Живая генерация AI, загрузка фото на Hugging Face, анонимные квоты, CORS/доступность внешних площадок. Прежние модели сохранены, но не объявлены всегда доступными.
- Экспертная педагогическая оценка всех карточек, юридическая проверка обработки детских данных, нагрузочное тестирование и гарантированная доступность бесплатных сервисов.

Перед использованием реальных данных выполните [настройку и живой приёмочный список](CLOUD_SETUP.md). Бесплатные тарифы ограничены; SMTP может требовать отдельного провайдера/домена. Синхронизация не заменяет резервную копию; автоматической очистки оставшихся объектов фото пока нет.
