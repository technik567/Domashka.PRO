# Проверки 4.6 — бесплатная очередь, Auto и служебный PNG

## Итог и границы исправления

**Исправлены дефекты клиентского подключения, но восстановление всех внешних моделей не подтверждено.**

- Pollinations получил два разных коротких синтетических вопроса и вернул законченные ответы. Второй занял **51.263 с**: старый 45-секундный предел оборвал бы его. Непотоковый запрос заменён штатной бесплатной потоковой очередью, не платным API и не обходом лимита.
- В дополнительном живом workflow **планирование прошло**, но следующий запрос ответа не завершился за **120 с**. Проверочный проход не начался. Стабильная работа полного цикла/длинных заданий **не заявляется**; тайм-аут не скрыт локальной заглушкой и не повторялся автоматически.
- Qwen 3.5 и Qwen 2.5 вернули скрытую ошибку `upstream`, в том числе Qwen 2.5 с уже правильным PNG. **Доступность Qwen не восстановлена; причина backend-отказа не установлена.** Их карточки сообщают о неуспешном контрольном запросе, не притворяясь мониторингом текущего доступа пользователя.
- Физический iPhone, HTML Viewer, реальные Auth/Turnstile и поиск через живую Supabase-функцию этим выпуском не проверены. Последние скриншоты пользователя относятся к уже опубликованному HTTPS-сайту 4.5, не к Viewer.

## Что исправлено в приложении

### Pollinations

Фиксированный прежний endpoint `https://text.pollinations.ai/openai`, без ключа/cookie/редиректов. Параметр **`stream:true`**, канонический model ID `openai-fast` (GPT-OSS 20B по каталогу площадки). Старое `openai` — допустимый alias, **оно не было доказанной причиной 402**.

[Опубликованный legacy origin](https://github.com/pollinations/pollinations/blob/bf4c219e3581821df582930b925533d4fcd9bec5/text.pollinations.ai/cloudflare-cache/src/origin.js) задаёт `FREE_INTERVAL_MS = 45000` и `canWait = params.stream || !weftEnabled(env)`: поток ожидает обычный бесплатный слот, непотоковый запрос в занятый интервал может получить 402. Это подтверждённое несоответствие прежних запросов частым этапам workflow, **не доказательство единственной причины исходного 402 на телефоне**. Тело того отказа не было известно. Семантика баланса нового keyed `gen.pollinations.ai` не переносится автоматически на legacy endpoint; приложение туда не переезжало.

`src/standalone/pollinationsGateway.js` и `backend/pollinations_gateway.py`:

- один запрос, **120 с** на заголовки/очередь/весь ответ, до 2 млн символов потока / 100 тыс. на событие и итоговый текст;
- SSE/UTF-8/CRLF, comments/heartbeats, JSON-совместимость только для ответа на тот же запрос; нужен `finish_reason:stop|length` либо `[DONE]` и непустой текст;
- промежуточный текст без завершения не принимается; `length` помечает возможную неполноту;
- только текст ответа: reasoning/tool fields не выводятся в статус, не записываются в историю и не идут следующему этапу;
- 402/429 остаются отказом маршрута, без чтения payment challenge, оплаты или повтора; безопасный числовой Retry-After — только пояснение;
- Stop, поздний fetch/read и зависший cancel не задерживают возврат браузеру; после отмены не запускаются следующие проходы;
- контекст ограничен до сети; прямая передача самого фото текстовому адаптеру отклоняется;
- Python HTTP bridge ждёт 135 с, а не прерывает этот маршрут прежним коротким лимитом.

### Последовательный Auto

В обоих вариантах приложения общий порядок из `shared/legacy-gateways.json`:

1. Текст: Pollinations; только после отказа — Qwen 3.5, затем Qwen 2.5.
2. Само изображение: только Qwen 3.5 / Qwen 2.5, без скрытого OCR, Pollinations или локального ответа.
3. Один **300-секундный бюджет** на весь Auto-проход, не по пять минут каждому резерву. Общий workflow остался **480 с**, максимум четыре логических прохода / два поиска.

Убран одновременный запуск трёх запросов и расход квоты проигравших маршрутов. Новые демо Gemma/Llama/Mistral/Qwen3 не добавлены в фон. Ручной выбор модели/старые настройки не меняются. Политика репетитора, account-scoped отмена, прямые фото и явно помеченные локальные резервы сохранены. Время/статус отображают реальную работу; проценты и скрытые мысли не добавлены.

### Qwen 2.5: настоящий дефект PNG

Image-only API требует изображение даже для текстового вопроса. Старый 16×16 PNG содержал неверный IDAT CRC и не распаковывался (`invalid distance too far back`). Загрузка файла с HTTP 200 сама по себе этого не проверяет.

Теперь один корректный **16×16 RGB белый PNG** используется JS/Python из общего JSON. Тесты проверяют CRC всех chunks, deflate/pixels, полное декодирование Pillow и совпадение реально отправленных multipart-байтов с эталоном. Переданное пользователем фото не заменяется белым фоном. Исправление необходимо, но живой отказ нового запроса показывает, что оно **не решает все проблемы внешнего демо**.

Qwen 3.5 [в исходнике Space](https://huggingface.co/spaces/Qwen/Qwen3.5-Omni-Offline-Demo/raw/main/app.py) вызывает Dashscope API владельца; Qwen 2.5 [использует `@spaces.GPU`](https://huggingface.co/spaces/developer0hye/Qwen2.5-VL-7B-Instruct/raw/main/app.py). Девять входов/выход истории index 4 и два входа соответственно совпали с адаптерами. Общий `upstream` не устанавливает ни GPU-квоту, ни CORS, ни одинаковую причину двух отказов. Сырые ошибки провайдера не раскрываются.
