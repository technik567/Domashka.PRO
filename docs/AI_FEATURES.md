# Ответы, режимы и помощник 4.3 — контракты и ограничения

Дата проверки документации/публичных GET-контрактов: **06.11.2026**. Это не отчёт о живом inference, CORS, SMTP или бесплатном остатке пользователя.

## Графики и Markdown

`shared/ai-features.json` — единая инструкция JS/Python. Fenced blocks `domashka-chart`, `chart`, `plot` интерпретируются как JSON, не код. Формула / line / scatter / bar; не более 4 графиков, 3×160 пар, 24 столбцов, 257 вычисляемых точек. Формула ≤400 символов, ≤180 токенов, глубина ≤32. `mathExpression.js` не использует eval, Function, свойства объектов, циклы, присваивание или импорты. По тем же правилам теперь работает график в «Калькуляторы».

Подписи экранируются, сырые модельные HTML и автоматические картинки не загружаются. Это важно для выдержек поиска: чужая страница не должна инициировать запрос с утечкой данных через `<img>`/SVG. График доступен в SVG/печати; текстовый/DOCX экспорт не превращает спецификацию в нативную диаграмму Word. Данные ИИ не считаются подтверждёнными измерениями. Численные особенности и алиасинг не решаются универсально: для особых точек нужна математическая проверка.

## Адаптивное рассуждение

- Низкий/средний/высокий всегда явно указывает тип поддержки.
- Gemini generateContent: allowlist `gemini-2.5-flash`, `gemini-2.5-flash-lite`, `gemini-2.5-pro`; `thinkingConfig.thinkingBudget` 512/2048/8192, `includeThoughts:false`. В общий output budget добавляется место для ответа. Thought parts отбрасываются.
- OpenRouter: только явный массив `reasoning.supported_efforts` каталога, содержащий выбранное значение; `null`/отсутствие — не подтверждение. Передаётся `reasoning:{effort,exclude:true}`, достаточный ограниченный max_tokens. Python получает этот подтверждённый режим через proxy; неизвестный канал остаётся инструкцией.
- Остальные модели: инструкция о проверке фактов/логики/допущений, без заявления об управлении скрытым budget. «Выкл.» не обещает отключить встроенное мышление модели. Родительская политика остаётся сильнее уровня.
- Источники: https://openrouter.ai/docs/guides/best-practices/reasoning-tokens ; https://ai.google.dev/gemini-api/docs/thinking . Контракты меняются; inference с личными ключами не выполнялся.

## Поиск Tavily

Пользователь подтвердил полный поиск с **ключом владельца сервера**, не личным AI-ключом каждого ученика.

1. Создать владельцу аккаунт **Tavily Researcher / Free** (документация на дату проверки: 1000 credits/month, без карты). Не включать PAYG, автоматическое пополнение/платную подписку. Если уже используются другие приложения, их расход уменьшает доступную квоту: приложение не видит общий остаток и не может обещать отсутствие тарификации для неправильно настроенного платного аккаунта владельца.
2. В Supabase Edge Secrets добавить **`TAVILY_API_KEY`**; секрет не отправлять в чат, не писать в HTML, `.env` в Git или переменные фронтенд-сборки. `SUPABASE_SERVICE_ROLE_KEY` платформа функции предоставляет сама; браузер его не получает.
3. Применить миграции в порядке имён, включая `20261106160243_domashka_web_search.sql`, и развернуть `web-search`. **В существующем проекте `zgfjfngcwtupqyirwfha` этот шаг уже выполнен; повторять SQL нельзя.**
4. `DOMASHKA_ALLOWED_ORIGINS` — точный origin опубликованного сайта, без `/`, не `*`. Это общий секрет-конфиг обеих функций. Auth redirects настраиваются отдельно. Внешняя функция имеет `verify_jwt=false` только потому, что сама проверяет bearer через `Auth.getUser`; это НЕ публичный анонимный поисковый прокси.
5. Проверить реальным аккаунтом удачный поиск/ссылки и отказы (нет ключа/квоты, запрещённая роль/Origin). Не расходовать реальную квоту нагрузочными тестами. В этой разработке использовались фикстуры, не живой Tavily.

`POST /functions/v1/web-search` принимает только `{query,requestId}` (3–300 символов, UUID). Не принимает историю, фото, AI-ключи, произвольный endpoint или параметры дорогого поиска. После Auth серверный RPC заново проверяет реальный сеанс, подтверждение почты родителя, disabled, password/session epoch, logout revoke и child allow_ai/tutor_only. Вызов RPC разрешён только service_role — пользователь не может напрямую исчерпать глобальную квоту.

Атомарный резерв: **900/месяц UTC глобально; 8/час, 30/сутки на пользователя**. Удаление пользователя не возвращает глобальные кредиты. Ledger хранит request ID/user ID/время, **не поисковую фразу, выдержки или секрет**; очищается до текущего/предыдущего месяца при следующей резервации. Функция не пишет запросы/ключи в console. Сам Tavily может обрабатывать/хранить запросы по своим правилам. Failed/timeout/cancel резерв не возвращается: провайдер мог уже выполнить запрос. Идемпотентный ID не вызывает второй поисковый запрос.

Upstream фиксирован: `https://api.tavily.com/search`, basic (1 credit), max_results 5, auto_parameters false, general, safe_search true, без answer/raw_content/images. Redirects запрещены; чтение ответа ограничено 100 KB/18 s. Сниппеты ≤1200 знаков. Внешние URLs фильтруются, страницы не загружаются приложением. Результаты передаются модели как недоверенные данные; настоящие возвращённые ссылки/время добавляет приложение, а не модель. Готовность или доступность источника не гарантируется. Нет результатов/ключа/права — явная ошибка, без подмены ответом по памяти. Локальный HTML и Python-сервер не используют owner-secret fallback; поиск только в облаке.

Источники: https://www.tavily.com/pricing ; https://docs.tavily.com/documentation/api-reference/endpoint/search . Bing RSS не используется из-за ограничений условий использования.

## Отдельный ИИ-помощник сайта

Каноническая публичная база: `shared/site-help.json` (23 темы), ручные проверяемые сведения о реальных контролах/ограничениях. Поиск по ней локальный; сам по себе не называется ИИ. Модель получает 3 подходящие темы, вопрос, до 4 предыдущих реплик окна, роль/раздел/версию и признаки режима, не личную тетрадь. При отсутствии темы — общие сведения и требование не выдумывать. Распространённые email/ключи/`пароль: ...` маскируются; это не надёжное распознавание всех секретов. Не вводите личные данные. История помощи только в памяти и удаляется при закрытии; история внешнего провайдера этим не удаляется.

Крупный кандидат без пользовательского ключа: официальный публичный Space **Qwen/Qwen3-VL-235B-A22B-Instruct-Demo**. GET runtime показал RUNNING/READY; `/gradio_api/info` и `app.py` подтвердили `add_text(history,text)` → `predict(_chatbot)` с общим state. Каждый вопрос создаёт новый криптографический session_hash; history передаётся явно и ограниченно. Ни OAuth token, ни cookie, ни встроенный ключ не используются. Нет загрузки пользовательских фото в помощник. Источник печатает prompts — предупреждение показано до отправки.

**GET metadata и доступный API не доказывают, что анонимный inference работает сейчас. Живой POST в этой среде не выполнялся.** Нет обещания «самая мощная в мире»/безлимита. До пяти минут ожидания, ошибки регистрации/квоты/протокола без обхода и без скрытого fallback. Взрослый может явно выбрать уже поддерживаемую Gemma 3 12B; это не обнуляет общую квоту HF. Для ребёнка применяется выбранный родителем бесплатный канал; запрет ИИ закрывает сетевую помощь. Личный платный API-ключ не используется. До облачного входа — только локальная справка.

Помощник не является инструментальным агентом: ничего сам не меняет/не отправляет. Ссылки из модели не активны, навигация только из curated topics с проверкой детского режима. Как и всякое инструкционное ограничение генеративной модели, оно не является математической гарантией поведения и не управляет другими сайтами.
