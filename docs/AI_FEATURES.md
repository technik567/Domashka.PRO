# Ответы, режимы и помощник 4.8 — контракты и ограничения

Мок-тесты не являются живым inference, CORS или проверкой квоты. В 4.6 отдельный короткий Node-прогон подтвердил два последовательных ответа Pollinations; оба старых Qwen вернули `upstream`. Дополнительный живой workflow принял план Pollinations, но запрос ответа истёк по 120-секундному дедлайну — завершённый цикл не подтверждён. Успех metadata не выдаётся за генерацию. Прежний Node-результат Tavily HTTP 200 / NASA относится к 4.4, не к живому поиску через Supabase. Физический телефон и production acceptance отдельно не подтверждены. [QA 4.6](QA_4.6.md) · [Исторический QA 4.4](QA_4.4.md#полученный-живой-результат).

## Изменения 4.8 — независимый поиск

Зависимость от первой генерации устранена архитектурно: **локальные правила → реальный поиск → первая генерация выбранной модели → проверки**. Если поиск не нужен, генерация начинается сразу; нет ни модельного планирования, ни команды, от которой зависит запуск Tavily. Следующие этапы не могут инициировать поиски. Teacher/reasoning/graphics/native-photo/OCR-контекст модели сохранён, но поисковая фраза строится отдельно только из текущего текстового условия.

Это заменяет 4.7, где обычный ответ либо запрос источников исходил от модели. Три ограниченных живых контроля 4.7 не дошли до Tavily; один диагностировал native `tool_calls`, после `tool_choice:none` другой дал `search-action-invalid`. Их неудачи остаются в [QA 4.7](QA_4.7.md), не переименованы в успех 4.8. Запрет native tools в JS/Python, фильтрация SSE и фиксированная безопасная диагностика сохранены. Внешний upstream Qwen/GPU-квота Gemma этим не исправляются.

Текущие результаты — [QA 4.8](QA_4.8.md). Обычный CI не вызывает модели. Новый opt-in probe: **один keyless Tavily до максимум одной Pollinations-генерации**, 160 секунд всего; без аккаунтов/фото/ключей/повторов. Пустое Node guest-хранилище моделирует только автономный режим, не облачную авторизацию. Отдельная диагностика делает один арифметический запрос формата, не запрос планирования/поиска.

## Сохранено из 4.6 — бесплатный маршрут

- **Тот же `https://text.pollinations.ai/openai`, `model:openai-fast`, `stream:true`.** В [исходнике legacy-сервиса](https://github.com/pollinations/pollinations/blob/bf4c219e3581821df582930b925533d4fcd9bec5/text.pollinations.ai/cloudflare-cache/src/origin.js) бесплатный слот — 45 с/IP, потоковые запросы ожидают его, а непотоковые могут попасть на 402 challenge. Ожидание штатного слота не меняет IP/квоту и не является оплатой. `openai` там допустимый alias, поэтому смена имени сама по себе не была причиной исправления.
- JS/Python используют полноценный SSE transport, **120 с** на заголовки/очередь/тело. Python-мост клиента — 135 с; Auto в обоих вариантах — **300 с суммарно**, workflow — прежние 480 с. Это не только увеличение тайм-аута: режим запроса изменён с отказа в занятом интервале на предусмотренное площадкой ожидание.
- Только `delta.content` и конечное `message.content` из совместимого JSON. `reasoning`, `reasoning_details`, tools не выводятся/не сохраняются/не передаются следующим этапам. Нужен `finish_reason:stop|length` либо `[DONE]`, непустой ответ; length даёт предупреждение. EOF без завершения — ошибка. Поток ≤2 млн символов, событие и итоговый текст ≤100 тыс.; контекст ≤48 тыс.
- Нет чтения тела HTTP-отказа/платёжного challenge, ключей, cookies, редиректов или повторов. 402/429 останавливают этот маршрут; безопасный числовой Retry-After показывается как совет, не запускает автоматический повтор. Stop и поздние ответы ограничены даже при некооперативном браузерном чтении.
- Auto: **текст → Pollinations → при отказе Qwen 3.5 → Qwen 2.5**. Только последовательные исходные маршруты, без фоновой гонки и новых демо. **Само фото → только Qwen**, без текстового Pollinations/скрытого OCR. Выбранная вручную модель никогда не меняется.
- Qwen 2.5 image-only API для текста получает исправный 16×16 RGB PNG из `shared/legacy-gateways.json`. Старый IDAT имел неверный CRC и не распаковывался. Общий файл для JS/Python проверяется реальным декодированием и сравнением upload. Пользовательские фото остаются исходными обработанными фото.
- Проверенный PNG **не устранил живой отказ Qwen 2.5**; Qwen 3.5 тоже вернул скрытую ошибку. Qwen 3.5 Space использует API Dashscope владельца, Qwen 2.5 — `@spaces.GPU`; общий `upstream` не доказывает GPU-квоту, CORS или одинаковую причину. Изменения Supabase ради такого отказа не делались.

## Исправления транспортов 4.5

Старые Qwen3.5/Qwen2.5-VL теперь используют ограниченный Gradio transport: общий бюджет upload/submit/SSE 300 с, свежий session_hash, strict event/path, финальный `complete`, пропуск пустых промежуточных component updates. В 4.5 Pollinations ожидался 45 с; с 4.6 — потоковая бесплатная очередь до 120 с, как описано выше. Python auto использует общий 300-секундный бюджет на свои исходные маршруты. Новые демо не добавлены в Auto. Ошибка Python-моста не дублируется прямым запросом из браузера.

`fetchAbortable`/`fetchWithTimeout` ограничивают даже некооперативные headers/body и освобождают поздний ответ; buffered body ≤16 МБ, Gradio имеет отдельный лимит. Явный OCR использует те же Qwen-адаптеры с бюджетом 60 с на маршрут; общий OCR ≤180 с, Python-мост OCR ≤150 с. Прежний OCR-каскад сохранён, прямое Vision не заменяется OCR. Закрытие reader/worker не задерживает отмену. Смена аккаунта/родительской политики исключает позднее принятие фото.

HTTP-статус остаётся видимым; непрозрачный браузерный отказ не диагностируется как доказанный CORS. В 4.8 этапы — `search-local`, `search-1`, `answer` и `review-N`: ошибка локальной подготовки/поиска предшествует любой генерации; при пропуске поиска ошибка модели остаётся настоящим отказом. Поиск не подменяется ответом по памяти. В receipt сохраняется только фиксированное служебное сообщение, без provider body.

[GET/OPTIONS-прогон](https://github.com/technik567/Domashka.PRO/actions/runs/44672142695) подтвердил метаданные и preflight у восьми HF API и preflight Pollinations/Tavily. **Генерация/поисковые POST/Supabase не вызывались**, настоящий ответ и телефон не подтверждены. [QA 4.5](QA_4.5.md).

## Графики и Markdown

`shared/ai-features.json` — единая инструкция JS/Python. Fenced blocks `domashka-chart`, `chart`, `plot` интерпретируются как JSON, не код. Формула / line / scatter / bar; не более 4 графиков, 3×160 пар, 24 столбцов, 257 вычисляемых точек. Формула ≤400 символов, ≤180 токенов, глубина ≤32. `mathExpression.js` не использует eval, Function, свойства объектов, циклы, присваивание или импорты. По тем же правилам теперь работает график в «Калькуляторы».

Подписи экранируются, сырые модельные HTML и автоматические картинки не загружаются. Это важно для выдержек поиска: чужая страница не должна инициировать запрос с утечкой данных через `<img>`/SVG. График доступен в SVG/печати; текстовый/DOCX экспорт не превращает спецификацию в нативную диаграмму Word. Данные ИИ не считаются подтверждёнными измерениями. Численные особенности и алиасинг не решаются универсально: для особых точек нужна математическая проверка.

## Ограниченный цикл ответа: реальные действия, не скрытые мысли

`src/standalone/workflow.js` — общий браузерный оркестратор решения, проверки черновика и уточнений; работает и с Python-мостом, отправляя туда отдельные проходы. Не запускает tools/код/URL из вывода модели. До **3** логических запросов модели, **1** поиска, **480 секунд** на операцию. Возможные транспортные шаги (upload, submit, SSE, OCR и прежний явный Auto) не считаются отдельными «проверочными проходами». Квоту удалённого сервиса приложение не измеряет.

- С поиском и без него: `off`/`low` — одна генерация, `medium` — две, `high` — три. Поиск запускается до первой генерации, модельный план не нужен.
- `off`: один ответ; `low`: один ответ + инструкция о короткой проверке результата.
- `medium`: ответ → ещё один запрос проверки с исправленным полным ответом.
- `high`: дополнительный проверочный запрос другим способом/проверкой допущений. Числовые равенства проверяются ограниченным `mathExpression.js` (только целая строка вида `(2+3)^2 = 25`, до 8, без переменных/единиц/исполнения кода); отсутствие подходящих равенств честно отмечается. Расхождение в итоговом ответе даёт предупреждение, не бейдж «верно».
- `auto`: локальная ограниченная эвристика по словам/длине/наличию фото. Это не модель оценки сложности и не гарантия оптимальной глубины.
- Проверяет **та же модель**, не независимый эксперт. «Проверочный проход завершён» означает получение ответа на отдельный запрос, не доказательство правильности.
- Контекст проверки сохраняет исходное условие и последние четыре реплики. Если черновик + инструкция + OCR не помещаются в безопасный предел подключения, проверка пропускается с явным предупреждением. Ошибка проверки оставляет последний полученный ответ с предупреждением, без автоматического повтора. Нельзя бесконечно уточнять/расходовать квоты.
- Нативные фото остаются фото на каждом проходе, старый OCR не восстанавливается поверх Vision. Распознанный текст кэшируется в памяти текущей операции, чтобы не запускать OCR заново на каждом этапе. Это не делает передачу фото конфиденциальной по отношению к внешнему провайдеру.
- В репетиторе усиление применяется к **одной подсказке**, не готовому решению. Поиск запрещён до сетевого вызова и дополнительно на сервере. Смена аккаунта/родительской политики прерывает работу.
- Stop отменяет ожидание, следующие действия и запись запоздалого ответа, но не обещает остановку чужого сервера/возврат квоты.

`WorkflowPanel` показывает только события, полученные от выполняющегося кода. Таймер измеряет время, не процент завершения. Запросы/источники видны подробно только в продвинутом режиме. Завершённая панель сворачивается. Сохраняется `cleanWorkflow`: ограниченные счётчики, время и короткие служебные события, **не мысли, ответы-черновики, ключи, полные provider body или поисковые фразы**. У импортированных чатов неподтверждённая запись workflow удаляется.

### Нативные параметры

- Gemini generateContent: allowlist `gemini-2.5-flash`, `gemini-2.5-flash-lite`, `gemini-2.5-pro`; `thinkingConfig.thinkingBudget` 512/2048/8192, `includeThoughts:false`, ограниченный output budget с местом для ответа. Thought parts отбрасываются.
- OpenRouter: только `reasoning.supported_efforts`, явно содержащий уровень. `null`/отсутствие — не подтверждение. `reasoning:{effort,exclude:true}`; Python получает подтверждённую возможность через proxy.
- Официальный Qwen3 Demo: `enable_thinking` в состоянии новой Gradio-сессии; начальное `true` известно из исходника. Для off один вызов `toggle_thinking` в той же сессии. `thinking_budget` 1/2/8 Ki-token; это параметр опубликованного контракта, не доказательство успешного live inference. Контракт в [PUBLIC_DEMOS.md](PUBLIC_DEMOS.md#новые-подключения-44--qwen3).
- Прочие каналы: инструкция плюс реальные отдельные проверочные проходы, **без заявления о внутреннем thinking-бюджете**. Off не обещает выключить скрытое мышление каждой модели.
- Источники: https://openrouter.ai/docs/guides/best-practices/reasoning-tokens ; https://ai.google.dev/gemini-api/docs/thinking . Личные ключи для живого прогона не использовались.

## Поиск Tavily

**Отдельного поля «что искать» нет.** `localSearchPlan.js` использует ограниченные детерминированные правила, не ИИ-классификатор. Явные просьбы найти источники и слова актуальности могут запустить поиск; обычная математика/объяснения обычно пропускаются. Ошибки классификации возможны. При пропуске добавляется явная подпись о локальном решении и непроверенных новых источниках.

### Граница данных и безопасная подготовка

- `api.solveHomework` передаёт `searchTaskText: cleanTask`, без фото-плейсхолдера/OCR; `checkDraft` — только `cleanCond`, без `cleanDraft`; `chatFollowup` — только введённый текущий вопрос, а для шаблонных действий пустую строку. Прямой workflow-вызов читает только последнюю реплику, если она user; checker без явной темы не читает свой составной prompt.
- Не читаются история, предыдущие ответы, фото, OCR, профиль или ключи. Фото при обычной генерации модели по-прежнему следуют выбранной политике Vision/OCR; это не обещание приватности относительно AI-провайдера.
- Вход для поисковой подготовки ≤2000 символов. Сначала проверяется весь ограниченный вход (до удаления слов), включая нормализованный Unicode. Очевидные контакты/секреты/адреса/коды/похожие ФИО, структурные данные/URL/код/служебные обёртки отклоняются. Это best-effort: не универсальная анонимизация; возможны ложные отказы, в том числе для полного имени публичного лица. Не вводить личные данные.
- Выбирается одна фраза текущей просьбы, удаляются служебные слова, дубликаты и пунктуация. Итог **3–180 символов, ≤12 значимых слов, один запрос** на любом reasoning-уровне. Длинная/неясная тема отклоняется, не обрезается наугад и не дополняется из истории. `validateSearchQuery` — второй транспортный фильтр, не единственная защита. Нет авторемонта моделью или вопроса в отдельном поле; подсказка просит уточнить обычное сообщение.
- `search-local` и `internet-skipped` — фактические локальные события. Поисковая фраза временно видна в advanced view, но не попадает в сохранённый receipt/экспорт.
- Модель никогда не получает разрешение на tool loop. `parseSearchAction` оставлен только как **детектор для отклонения** старого reserved block/control JSON, не как источник запросов. Неверные команды и native tools не исполняются/не чинятся и не планируют следующие шаги.

### Keyless и ключи

- Документированный официальный режим без ключа: `POST https://api.tavily.com/search`, header **`X-Tavily-Access-Mode: keyless`**. Числовой размер keyless-квоты не заявлен. Источник: https://docs.tavily.com/documentation/keyless .
- Облачный сайт: только авторизованная `web-search`, не анонимный прокси. Локальный HTML/Python UI: напрямую из браузера, при разрешении CORS/WebView. Никакого скрытого перехода с облачного поиска на прямой для обхода запрета/квоты.
- Владелец может хранить `TAVILY_API_KEY` в Edge Secrets. Это серверный секрет, не фронтенд env и не HTML. **Необязателен начиная с исходника 4.4.** Функция уже отдельно обновлена и прочитана обратно: **v4 ACTIVE / source 4.5**. В 4.6–4.8 нет нового Edge deployment или изменения секретов.
- В Настройки → Продвинутый взрослый может явно ввести свой Tavily-ключ (получить: https://app.tavily.com/) и выполнить один тестовый поиск. Поле парольное; значение после подключения очищается. Сам ключ только в памяти модуля до перезагрузки/смены аккаунта/политики. Не localStorage, не study export, не лог, не модель, не облачная preference. Дети не могут задать ключ. В cloud body это request-scoped `searchKey`; функция его не сохраняет, не возвращает и не журналирует. Тот же серверный резерв обязателен. Приоритет: явно переданный ключ → owner key → keyless. Ошибка не приводит к автоматическому перебору.
- Для ключевого Free-аккаунта документация указывает 1000 credits/month/no card; это **не** число keyless. Нельзя включать PAYG/автопополнение. Приложение не проверяет чужой биллинг и не может обещать отсутствие списаний у ключа, которому пользователь сам подключил платный тариф. Источник: https://docs.tavily.com/documentation/api-credits .

### Серверный контракт и неизменённая защита

`POST /functions/v1/web-search`: только `{query,requestId,searchKey?}`. query 3–300 знаков, requestId UUID. Ни истории, ни фото, ни произвольного endpoint, ни параметров дорогого поиска. Только точный разрешённый Origin; отсутствие Origin запрещено. Внутренний `Auth.getUser` и проверка настоящего session ID; `verify_jwt=false` не означает отсутствие авторизации. Service-role RPC повторно проверяет сеанс, disabled/password epoch/logout revoke и child allow_ai/tutor_only.

Резерв **900/месяц UTC на проект; 8/час, 30/сутки на пользователя**, для всех трёх режимов ключа. Ledger хранит ID/время, не запрос/результаты/ключ. Ошибка/отмена резерв не возвращает: провайдер мог уже выполнить поиск. Повторный requestId не выполняет второй upstream.

Upstream всегда basic, max_results=5, general, auto_parameters=false, safe_search=true, без answer/raw_content/images. Один запрос, redirects запрещены, ответ ≤100 КБ/18 с; весь Edge-запрос Auth/RPC/Tavily ≤30 с, облачный клиент ≤35 с, прямой локальный ≤22 с. Разрешённый OPTIONS независим от service credentials, ошибки содержат только фиксированный code и версию. `SEARCH_SETUP_REQUIRED` / `SEARCH_BACKEND_UNAVAILABLE` / `SEARCH_UPSTREAM_UNAVAILABLE` различают настройку, проверки сервера и отказ поисковика; 503 без code не получает выдуманную причину. Один поисковый запрос независимо от глубины, до пяти валидированных и дедуплицированных источников. Выдержка ≤1200 знаков. Заголовки/выдержки считаются недоверенными **данными**, не инструкциями. Полные страницы не скачиваются; JS/HTML/картинки из результатов не выполняются. Приложение добавляет настоящий список URL и время. URL, выдуманные моделью вне возвращённого набора, удаляются, неизвестные номера источников помечаются. Это не гарантирует поддержки каждого вывода найденным источником.

Ошибка локальной подготовки/поиска, запрет, лимит и пустой набор останавливают работу до модели. Если правила пропустили поиск и модель отказала, остаётся ошибка; локальный запасной ответ при Internet auto отключён. Автоповторов нет.

**Успешный поиск + отказ первой генерации:** `sourcesOnly:true`; отображаются реальные заголовки, выдержки и footer с исходными URL. Заметный заголовок уточняет: это **не готовое решение и не ответ выбранной модели**. `used` и timeline отличают результат от ИИ-ответа; успешной предыдущей генерации нет, metadata не приписывает обработку Vision/OCR и не восстанавливает старый OCR; проверки, повторы и смена модели не запускаются. Чужие заголовки/выдержки кодируются numeric entities до Markdown, чтобы картинки, HTML, формулы и GFM autolink не стали активными. Ссылки активны только в проверенном footer. Raw provider error не сохраняется. Отмена и смена политики/аккаунта не публикуют такой fallback. Если поиск не удался, выдержки не выдумываются. Такие результаты сохраняются в истории, но не начисляют solve/check/XP и не вызывают capture ошибок ученика. `cleanWorkflow` сохраняет прежние максимумы 4/2 для совместимости исторических receipts; новый workflow сам ограничен 3/1.

Пользователь может явно выключить интернет для обычного ответа. SQL-миграция `20261106160243_domashka_web_search.sql` в существующем проекте уже установлена; **не повторять и не менять**. Функция 4.5 уже опубликована отдельно; для 4.8 повторной публикации не требуется. Auth/family/account-access и данные не менялись. [Статус](CLOUD_LAUNCH.md).

## Отдельный ИИ-помощник сайта

Каноническая публичная база: `shared/site-help.json` (23 темы), ручные проверяемые сведения о реальных контролах/ограничениях. Поиск по ней локальный; сам по себе не называется ИИ. Модель получает 3 подходящие темы, вопрос, до 4 предыдущих реплик окна, роль/раздел/версию и признаки режима, не личную тетрадь. При отсутствии темы — общие сведения и требование не выдумывать. Распространённые email/ключи/`пароль: ...` маскируются; это не надёжное распознавание всех секретов. Не вводите личные данные. История помощи только в памяти и удаляется при закрытии; история внешнего провайдера этим не удаляется.

Крупный кандидат без пользовательского ключа: официальный публичный Space **Qwen/Qwen3-VL-235B-A22B-Instruct-Demo**. Каждый вопрос создаёт новый криптографический session_hash; history передаётся явно и ограниченно. Ни OAuth token, ни cookie, ни встроенный ключ не используются. Нет загрузки пользовательских фото в помощник. Источник печатает prompts — предупреждение показано до отправки.
