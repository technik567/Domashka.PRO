# Ответы, режимы и помощник 4.4 — контракты и ограничения

Контракты 4.4 проверены по публичной документации/GET-описаниям; сетевой POST к Qwen3 и Tavily из среды разработки закончился HTTP 000 (соединение недоступно). Мок-тесты не являются живым inference, CORS или проверкой квоты. Ранее установленный Supabase backend в этом обновлении не изменялся.

## Графики и Markdown

`shared/ai-features.json` — единая инструкция JS/Python. Fenced blocks `domashka-chart`, `chart`, `plot` интерпретируются как JSON, не код. Формула / line / scatter / bar; не более 4 графиков, 3×160 пар, 24 столбцов, 257 вычисляемых точек. Формула ≤400 символов, ≤180 токенов, глубина ≤32. `mathExpression.js` не использует eval, Function, свойства объектов, циклы, присваивание или импорты. По тем же правилам теперь работает график в «Калькуляторы».

Подписи экранируются, сырые модельные HTML и автоматические картинки не загружаются. Это важно для выдержек поиска: чужая страница не должна инициировать запрос с утечкой данных через `<img>`/SVG. График доступен в SVG/печати; текстовый/DOCX экспорт не превращает спецификацию в нативную диаграмму Word. Данные ИИ не считаются подтверждёнными измерениями. Численные особенности и алиасинг не решаются универсально: для особых точек нужна математическая проверка.

## Ограниченный цикл ответа: реальные действия, не скрытые мысли

`src/standalone/workflow.js` — общий браузерный оркестратор решения, проверки черновика и уточнений; работает и с Python-мостом, отправляя туда отдельные проходы. Не запускает tools/код/URL из вывода модели. До **4** логических запросов модели, **2** поисков, **480 секунд** на операцию. Возможные транспортные шаги (upload, submit, SSE, OCR и прежний явный Auto) не считаются отдельными «проверочными проходами». Квоту удалённого сервиса приложение не измеряет.

- `off`: один ответ; `low`: один ответ + инструкция о короткой проверке результата.
- `medium`: ответ → ещё один запрос проверки с исправленным полным ответом.
- `high`: дополнительный проверочный запрос другим способом/проверкой допущений. Числовые равенства проверяются ограниченным `mathExpression.js` (только целая строка вида `(2+3)^2 = 25`, до 8, без переменных/единиц/исполнения кода); отсутствие подходящих равенств честно отмечается. Расхождение в итоговом ответе даёт предупреждение, не бейдж «верно».
- `auto`: локальная ограниченная эвристика по словам/длине/наличию фото. Это не модель оценки сложности и не гарантия оптимальной глубины.
- Проверяет **та же модель**, не независимый эксперт. «Проверочный проход завершён» означает получение ответа на отдельный запрос, не доказательство правильности.
- Контекст проверки сохраняет исходное условие и последние четыре реплики. Если черновик + инструкция + OCR не помещаются в безопасный предел подключения, проверка пропускается с явным предупреждением. Ошибка проверки оставляет последний полученный ответ с предупреждением, без автоматического повтора. Нельзя бесконечно уточнять/расходовать квоты.
- Нативные фото остаются фото на каждом проходе, старый OCR не восстанавливается поверх Vision. Распознанный текст кэшируется в памяти текущей операции, чтобы не запускать OCR заново на каждом этапе. Это не делает передачу фото конфиденциальной по отношению к внешнему провайдеру.
- В репетиторе усиление применяется к **одной подсказке**, не готовому решению. Поиск запрещён до сетевого вызова и дополнительно на сервере. Смена аккаунта/родительской политики прерывает работу.
- Stop отменяет ожидание, следующие действия и запись запоздалого ответа, но не обещает остановку чужого сервера/возврат квоты.

`WorkflowPanel` показывает только события, полученные от выполняющегося кода. Таймер измеряет время, не процент завершения. Запросы/источники видны подробно только в продвинутом режиме. Завершённая панель сворачивается. Сохраняется `cleanWorkflow`: ограниченные счётчики, время и короткие служебные события, **не мысли, ответы-черновики, ключи, полные provider body или поисковые фразы**. У импортированных чатов неподтверждённая запись workflow удаляется.

### Нативные параметры

- Gemini generateContent: allowlist `gemini-2.5-flash`, `gemini-2.5-flash-lite`, `gemini-2.5-pro`; `thinkingConfig.thinkingBudget` 512/2048/8192, `includeThoughts:false`, ограниченный output budget с местом для ответа. Thought parts отбрасываются.
- OpenRouter: только `reasoning.supported_efforts`, явно содержащий уровень. `null`/отсутствие — не подтверждение. `reasoning:{effort,exclude:true}`; Python получает подтверждённую возможность через proxy.
- Официальный Qwen3 Demo: `enable_thinking` в состоянии новой Gradio-сессии; начальное `true` известно из исходника. Для off один вызов `toggle_thinking` в той же сессии. `thinking_budget` 1/2/8 Ki-token; это параметр опубликованного контракта, не доказательство успешного live inference. Контракт в [PUBLIC_DEMOS.md](PUBLIC_DEMOS.md#новые-подключения-44--qwen3).
- Прочие каналы: инструкция плюс реальные отдельные проверочные проходы, **без заявления о внутреннем thinking-бюджете**. Off не обещает выключить скрытое мышление каждой модели.
- Источники: https://openrouter.ai/docs/guides/best-practices/reasoning-tokens ; https://ai.google.dev/gemini-api/docs/thinking . Личные ключи для живого прогона не использовались.

## Поиск Tavily

**Отдельная пользовательская фраза удалена.** При `webSearch:auto` перед ответом та же модель возвращает строго ограниченный JSON:

```json
{"search":true,"queries":["короткий минимальный запрос"]}
```

Либо `{"search":false,"queries":[]}`. Неизвестные поля/неверные типы/больше 1 запроса (2 для high)/более 4096 знаков ответа отвергаются. Это план публичного действия, **не chain-of-thought**. Дальнейший поиск выполняет только фиксированный код, не инструкция из страницы.

Модель сама решает необходимость и пишет минимальный запрос. Очевидные email/телефоны/секреты/резервные коды/управляющие символы отклоняются до отправки. Это best-effort минимизация, не универсальный детектор ФИО/чувствительной информации. Пользователь не должен вводить личные данные. Только короткая фраза уходит поисковику; планирование может использовать фото/контекст у выбранной AI-модели, как обычный запрос.

### Keyless и ключи

- Документированный официальный режим без ключа: `POST https://api.tavily.com/search`, header **`X-Tavily-Access-Mode: keyless`**. Числовой размер keyless-квоты не заявлен. Источник: https://docs.tavily.com/documentation/keyless .
- Облачный сайт: только авторизованная `web-search`, не анонимный прокси. Локальный HTML/Python UI: напрямую из браузера, при разрешении CORS/WebView. Никакого скрытого перехода с облачного поиска на прямой для обхода запрета/квоты.
- Владелец может хранить `TAVILY_API_KEY` в Edge Secrets. Это серверный секрет, не фронтенд env и не HTML. **Необязателен после обновления функции 4.4.** На действующем проекте ещё установлен прежний v2; в этой работе deployment не выполнялся.
- В Настройки → Продвинутый взрослый может явно ввести свой Tavily-ключ (получить: https://app.tavily.com/) и выполнить один тестовый поиск. Поле парольное; значение после подключения очищается. Сам ключ только в памяти модуля до перезагрузки/смены аккаунта/политики. Не localStorage, не study export, не лог, не модель, не облачная preference. Дети не могут задать ключ. В cloud body это request-scoped `searchKey`; функция его не сохраняет, не возвращает и не журналирует. Тот же серверный резерв обязателен. Приоритет: явно переданный ключ → owner key → keyless. Ошибка не приводит к автоматическому перебору.
- Для ключевого Free-аккаунта документация указывает 1000 credits/month/no card; это **не** число keyless. Нельзя включать PAYG/автопополнение. Приложение не проверяет чужой биллинг и не может обещать отсутствие списаний у ключа, которому пользователь сам подключил платный тариф. Источник: https://docs.tavily.com/documentation/api-credits .

### Серверный контракт и неизменённая защита

`POST /functions/v1/web-search`: только `{query,requestId,searchKey?}`. query 3–300 знаков, requestId UUID. Ни истории, ни фото, ни произвольного endpoint, ни параметров дорогого поиска. Только точный разрешённый Origin; отсутствие Origin запрещено. Внутренний `Auth.getUser` и проверка настоящего session ID; `verify_jwt=false` не означает отсутствие авторизации. Service-role RPC повторно проверяет сеанс, disabled/password epoch/logout revoke и child allow_ai/tutor_only.

Резерв **900/месяц UTC на проект; 8/час, 30/сутки на пользователя**, для всех трёх режимов ключа. Ledger хранит ID/время, не запрос/результаты/ключ. Ошибка/отмена резерв не возвращает: провайдер мог уже выполнить поиск. Повторный requestId не выполняет второй upstream.

Upstream всегда basic, max_results=5, general, auto_parameters=false, safe_search=true, без answer/raw_content/images. Один запрос, redirects запрещены, ответ ≤100 КБ/18 с (клиент ≤22 с). До двух запросов на высоком уровне, источники объединяются попеременно и дедуплицируются, максимум пять. Выдержка ≤1200 знаков. Заголовки/выдержки считаются недоверенными **данными**, не инструкциями. Полные страницы не скачиваются; JS/HTML/картинки из результатов не выполняются. Приложение добавляет настоящий список URL и время. URL, выдуманные моделью вне возвращённого набора, удаляются, неизвестные номера источников помечаются. Это не гарантирует поддержки каждого вывода найденным источником.

Плохой план, ошибка поиска, запрет, лимит и пустой набор приводят к объяснённому отказу, не поисковому ответу по памяти. Автоповторов нет. Пользователь может явно выключить интернет для обычного ответа. SQL-миграция `20261106160243_domashka_web_search.sql` в существующем проекте уже установлена; **не повторять и не менять**. 4.4 требует только обновления функции; Auth/family/account-access и данные не менялись. [Статус](CLOUD_LAUNCH.md).

## Отдельный ИИ-помощник сайта

Каноническая публичная база: `shared/site-help.json` (23 темы), ручные проверяемые сведения о реальных контролах/ограничениях. Поиск по ней локальный; сам по себе не называется ИИ. Модель получает 3 подходящие темы, вопрос, до 4 предыдущих реплик окна, роль/раздел/версию и признаки режима, не личную тетрадь. При отсутствии темы — общие сведения и требование не выдумывать. Распространённые email/ключи/`пароль: ...` маскируются; это не надёжное распознавание всех секретов. Не вводите личные данные. История помощи только в памяти и удаляется при закрытии; история внешнего провайдера этим не удаляется.

Крупный кандидат без пользовательского ключа: официальный публичный Space **Qwen/Qwen3-VL-235B-A22B-Instruct-Demo**. GET runtime показал RUNNING/READY; `/gradio_api/info` и `app.py` подтвердили `add_text(history,text)` → `predict(_chatbot)` с общим state. Каждый вопрос создаёт новый криптографический session_hash; history передаётся явно и ограниченно. Ни OAuth token, ни cookie, ни встроенный ключ не используются. Нет загрузки пользовательских фото в помощник. Источник печатает prompts — предупреждение показано до отправки.

**GET metadata и доступный API не доказывают, что анонимный inference работает сейчас. Живой POST в этой среде не выполнялся.** Нет обещания «самая мощная в мире»/безлимита. До пяти минут ожидания, ошибки регистрации/квоты/протокола без обхода и без скрытого fallback. Взрослый может явно выбрать уже поддерживаемую Gemma 3 12B; это не обнуляет общую квоту HF. Для ребёнка применяется выбранный родителем бесплатный канал; запрет ИИ закрывает сетевую помощь. Личный платный API-ключ не используется. До облачного входа — только локальная справка.

Помощник не является инструментальным агентом: ничего сам не меняет/не отправляет. Ссылки из модели не активны, навигация только из curated topics с проверкой детского режима. Как и всякое инструкционное ограничение генеративной модели, оно не является математической гарантией поведения и не управляет другими сайтами.
