# Домашка.ПРО 4.1 — полная инструкция для компьютера и телефона

> **Главный файл для обычного запуска — `Domashka_PRO.html`.** Это готовое приложение, а не исходный код. На компьютере его можно открыть без установки Python и Node.js. Для телефона, особенно iPhone, рекомендуется версия по HTTPS.
>
> Приложение не заменяет учителя: проверяйте вычисления, факты и школьные требования. Облачный ИИ может ошибаться даже при уверенном ответе.

## 1. Какой способ запуска выбрать

| Что нужно | Как запускать |
|---|---|
| Пользоваться на компьютере без установки программ | Скачать **`Domashka_PRO.html`** и открыть в современном браузере |
| Пользоваться на Android | Лучше открыть HTTPS-ссылку; локальный HTML тоже можно попробовать, если браузер и файловый менеджер разрешают запуск |
| Пользоваться на iPhone/iPad | Открыть **HTTPS-ссылку в Safari**; просмотр HTML в приложении «Файлы» не считается полноценным запуском |
| Разместить сайт для семьи | Один раз включить GitHub Pages по разделу 5; каждому устройству дать ссылку |
| Запустить Python API или менять код | Скачать исходники и выполнить команды из раздела 14 |

Готовый HTML находится **в корне репозитория**. Если изменения ещё находятся в Pull Request, переключите ветку на ветку этого PR; после объединения выбирайте `main`.

Не путайте файлы:

- **`Domashka_PRO.html`** — актуальное готовое приложение.
- **`index.html` в корне исходников** — входной файл разработки; двойной щелчок по нему не запускает готовый сайт.
- **`USER_GUIDE.txt`** — полная текстовая копия этой инструкции; также включена в переносимый ZIP под именем `ПОЛНАЯ_ИНСТРУКЦИЯ.txt`.
- **`Domashka_PRO_Portable.zip`** — необязательный переносимый комплект, который создаётся сборкой: приложение, инструкции, ярлыки. Этот ZIP не хранится в Git.
- **`workspace-…zip`** — старый исходный снимок 3.2, а не последняя версия приложения.
- **`src/`, `backend/`, `tests/`** — исходники и проверки для дальнейшей разработки. Для запуска готового HTML скачивать их не нужно.

<a id="pc"></a>
## 2. Компьютер: Windows, macOS, Linux

### Скачать и открыть

1. Откройте репозиторий `technik567/Domashka.PRO` в обычном браузере. В мобильном приложении GitHub при необходимости выберите открытие страницы во внешнем браузере.
2. Перейдите к **`Domashka_PRO.html`** в нужной ветке.
3. Нажмите **Download raw file / Скачать исходный файл** — значок загрузки или пункт меню файла. Название и расположение могут отличаться в разных версиях интерфейса GitHub. Если GitHub сообщает, что файл слишком большой для просмотра, это не ошибка: его всё равно можно скачать.
4. Сохраните именно файл приложения, а не веб-страницу интерфейса GitHub. Проверьте имя **`Domashka_PRO.html`**, без дополнительного `.txt`.
5. Переместите его в постоянную папку, например `Документы/ДомашкаПРО`. В дальнейшем лучше не менять имя и расположение без резервной копии чатов.
6. Дважды щёлкните по файлу. Если он открылся как текст, выберите **«Открыть с помощью» → браузер**. Подойдут актуальные Chrome, Edge, Firefox; на macOS также Safari, с учётом ограничений отдельных функций браузера.
7. Вы должны увидеть интерфейс Домашка.ПРО, а не строки HTML-кода. Адрес локального запуска обычно начинается с `file://`.

Если у вас переносимый ZIP, сначала **распакуйте его целиком**, затем откройте `Domashka_PRO.html` из распакованной папки. Ярлыки запуска необязательны; при предупреждениях ОС проще открыть сам HTML.

### Ежедневное использование

- Открывайте тот же файл в том же обычном, не приватном профиле браузера.
- Можно создать ярлык файла на рабочем столе. Это ярлык, а не установка отдельной программы.
- Для работы по HTTPS на компьютере действуют те же шаги, что и для телефона: открыть опубликованную ссылку и добавить её в закладки.
- В HTTPS/серверной версии на широком экране есть кнопка скачивания `.HTML`. Она скачивает программу, **не резервную копию ваших данных**.
- Интернет нужен облачным нейросетям и части распознавания, но не большинству локальных справочных и расчётных инструментов.

## 3. Телефон Android

### Рекомендуется: сайт по HTTPS

1. Если постоянной ссылки ещё нет, владелец репозитория один раз выполняет раздел 5.
2. Откройте полученную ссылку в **Chrome** или другом современном полноценном браузере, а не внутри чата, GitHub или файлового просмотрщика.
3. Выберите класс, настройте ИИ по разделу 6.
4. Для быстрого доступа откройте меню браузера и выберите **«Добавить на главный экран»** или аналогичный пункт. Если его нет, сохраните закладку.
5. При работе с фото нажмите кнопку с камерой либо выберите снимок из галереи. Если браузер спрашивает разрешение на фото/камеру, разрешите его только при необходимости. Названия системных запросов зависят от Android и браузера.

Внизу экрана находятся разделы: **«Решить», «Семья», «Проверка», «Дневник», «Тесты», «Точные», «Шпаргалки»**. В детском режиме остаются репетитор, семья, дневник и шпаргалки. История открывается кнопкой с изображением диалога вверху.

### Если хотите пользоваться скачанным HTML

1. Скачайте именно `Domashka_PRO.html`, а не страницу GitHub.
2. В «Загрузках» или файловом менеджере выберите **«Открыть с помощью» → браузер**, если такой вариант доступен.
3. Проверьте, что работают кнопки и после закрытия/повторного открытия сохраняется выбранный класс.
4. Если открывается только предпросмотр, код, пустой экран либо браузера нет среди вариантов, используйте HTTPS-версию. Поддержка локальных `file://` и `content://` зависит от устройства; гарантировать её на всех Android нельзя.

Не рассчитывайте на локальный файл, если требуется надёжное сохранение родительского режима: сначала проверьте сохранение и повторное открытие именно на этом устройстве.

<a id="ios"></a>
## 4. iPhone и iPad

1. Получите опубликованную **HTTPS-ссылку** (раздел 5).
2. Откройте её в **Safari**, не во встроенном просмотрщике мессенджера или GitHub.
3. Настройте класс и модель. Для повседневной работы используйте один и тот же браузер и адрес.
4. Для ярлыка нажмите **«Поделиться» → «На экран “Домой”» → «Добавить»**, если этот пункт доступен. Либо добавьте обычную закладку.
5. Чтобы приложить задание, используйте кнопку камеры/загрузки и выберите съёмку, медиатеку или файл в системном меню. Разрешения выдаются iOS, а не самим сайтом.
6. После настройки родительского режима закройте и снова откройте сайт именно тем способом, которым будет пользоваться ребёнок, и проверьте наличие зелёной плашки режима.

### Если в HTML Viewer нажатие камеры закрывает приложение

Начиная с версии 3.5 **не вызывается прямой захват камеры** в распознанном iOS-просмотрщике, локальном файле и на HTTP-странице. Вместо него есть **«Как снять фото»** и пояснение:

1. Снимите задание обычным приложением **«Камера»** iPhone.
2. Вернитесь в Домашка.ПРО → **«Галерея»** и выберите **готовый снимок**, не системный пункт «Снять фото».
3. Если даже выбор готового файла закрывает HTML Viewer, используйте обычную вкладку Safari с HTTPS-ссылкой. При возможности сохраните историю JSON до смены способа запуска.

Завершение самого стороннего приложения нельзя перехватить или исправить JavaScript-кодом страницы. Определение WebView эвристическое; некоторые ярлыки/просмотрщики тоже попадут под защитное ограничение. **Реальный HTML Viewer/iPhone не тестировался**, поэтому это защитный обход, а не обещание устранить любой нативный сбой. Для обычной вкладки Safari по HTTPS и совместимых Android камера остаётся доступной при разрешении ОС.

**Важно:** скачанный HTML в приложении **«Файлы» / Quick Look** может быть показан как документ, без полноценного выполнения JavaScript и сохранения данных. Поэтому обещания «откройте HTML на любом iPhone двойным касанием» неверны. Надёжный основной способ для iOS — HTTPS-сайт.

Добавление на домашний экран **не означает автоматическую офлайн-установку**: у приложения нет service worker для гарантированного офлайн-запуска сайта. Хранилище домашнего ярлыка и вкладки также может отличаться в зависимости от версии ОС. Настройки и режим проверяйте в том способе запуска, которым действительно пользуетесь.

<a id="pages"></a>
## 5. Постоянная ссылка через GitHub Pages

Это необязательная публикация **клиентской HTML-версии**, без Python-сервера. Обычному посетителю сайта аккаунт GitHub не нужен. Управлять публикацией должен владелец репозитория или пользователь с нужными правами.

### Настроить один раз

1. Убедитесь, что Pull Request с нужной версией (для этих изменений — 4.0) объединён в **`main`**. В ней должны быть `Domashka_PRO.html`, `scripts/prepare_pages.py` и `.github/workflows/pages.yml`.
2. Откройте репозиторий в браузере → **Settings → Pages**. На телефоне для этих настроек иногда удобнее режим полной версии сайта.
3. В блоке **Build and deployment** выберите **Source: GitHub Actions**.
4. Перейдите во вкладку **Actions**. При необходимости разрешите использование Actions для этого репозитория.
5. Выберите workflow **Publish website (GitHub Pages)**.
6. Нажмите **Run workflow**, выберите ветку **`main`**, затем подтвердите запуск. Другие ветки этим workflow не публикуются.
7. Дождитесь успешного завершения этапа `deploy`. Если GitHub требует подтверждение среды `github-pages`, выполните его в интерфейсе владельца.
8. Откройте URL из результата deployment или из **Settings → Pages**. Именно этот URL является источником истины.

Для текущего имени владельца и репозитория стандартный ожидаемый адрес без собственного домена:

```text
https://technik567.github.io/Domashka.PRO/
```

**Адрес выше заработает только после успешной настройки и публикации.** Наличие ссылки в инструкции не означает, что сайт уже опубликован.

Workflow выкладывает только готовый сайт: копию `Domashka_PRO.html` под именем `index.html`, сам `Domashka_PRO.html` для скачивания и `.nojekyll`. Это **не исходный `index.html` из корня проекта**. Кнопка скачивания использует относительный путь и работает под `/Domashka.PRO/`.

### После обновления

После объединения новой версии HTML в `main` повторите **Actions → Publish website (GitHub Pages) → Run workflow → main**. Публикация намеренно запускается вручную: обычный push сам по себе не включает и не обновляет хостинг.

### Важные ограничения

- Не включайте вместо этого публикацию «из корня ветки» без подготовки: там лежит `index.html` для разработки, а не готовая главная страница.
- GitHub Pages не запускает `server.py`. Запросы ИИ идут из браузера к внешним сервисам; доступность зависит от интернета, правил провайдера и CORS.
- Публикация не создаёт общий аккаунт, не синхронизирует дневник/чаты и не добавляет централизованный родительский контроль.
- Не вставляйте API-ключи в HTML, исходники или workflow. Каждый пользователь вводит свой ключ в настройках своего браузера.
- Если Pages недоступен по правилам аккаунта/организации, готовые файлы из `python3 scripts/prepare_pages.py` можно разместить на другом статическом HTTPS-хостинге. Пользуйтесь чистой папкой публикации и не выкладывайте серверные данные.

## 6. Первый запуск и выбор нейросети

### Базовая настройка

1. Выберите **класс 1–11** в верхней панели.
2. На широком экране также доступна **цель обучения**: обычный урок, ВПР, ОГЭ, ЕГЭ, олимпиада. На узком мобильном экране этот переключатель скрыт; выбор класса остаётся доступен.
3. Кнопкой луны/солнца выберите светлую или тёмную тему.
4. Нажмите **шестерёнку ИИ** вверху. На телефоне название модели может быть скрыто — нажимайте сам значок.
5. Выберите провайдера. Для бесплатного облачного режима модель выбирается **в самом чате**, под настройками формата ответа; для OpenRouter/Gemini/своего API модель и ключ остаются в этом окне.
6. Нажмите **«Проверить соединение»**, дождитесь результата и затем **«Сохранить настройки»**. Проверка отправляет небольшой настоящий запрос и может расходовать квоту провайдера; она не засчитывает локальную подсказку как доступный облачный ИИ.

Если включён детский режим, кнопка настроек приведёт к родительскому окну. Сначала отключите режим действующим паролем, измените настройки и снова включите защиту.

### Бесплатный облачный ИИ без ключа

- Оставьте провайдер **«Бесплатный облачный ИИ»** и в чате «Реши со мной» найдите блок **«Нейросеть для ответа · без ключа»**. Выбор сразу сохраняется для следующих запросов, отдельная кнопка сохранения не нужна. В окне настроек есть переход **«Сохранить и выбрать модель в чате»**.
- Для начала можно оставить **«Автовыбор»**. Он резервирует запросы между прежними Qwen/Pollinations; **новые демо выбираются вручную**, чтобы не расходовать их квоту в фоне.
- Прежние варианты **Qwen 3.5 Omni**, **Pollinations** и **Qwen 2.5 VL** сохранены. Pollinations сам определяет внутреннюю модель сервиса; это один маршрут, а не каталог Google/Llama.
- В **4.1 добавлены пять отдельных моделей**: **Google Gemma 3 12B**, **Google Gemma 3n E4B**, **Google Gemma 2 9B**, **Meta Llama 3.2 3B**, **Mistral 7B v0.3**. Итого **8 облачных вариантов + автовыбор**. Это публичные демо Hugging Face: не нужны ваш API-ключ, регистрация в Google/Hugging Face и скачивание весов на телефон, пока площадка разрешает анонимный запрос.
- Google **Gemma — не Gemini API**. Две визуальные Gemma подходят для текста и одного изображения; Gemma 2, Llama и Mistral — для текстовых заданий/OCR. Llama маленькая, особенно ориентируйтесь на короткие английские вопросы; русский и сложную математику перепроверяйте.
- При ошибке конкретный выбор не заменяется другим незаметно. Нет автоматического повтора, перехода к платной модели или предложения встроить чужой ключ. Ваш прежний сохранённый выбор не меняется при обновлении.

#### Квота новых демо: больше моделей — не больше бесплатного времени

На **06.11.2026** [документация Hugging Face ZeroGPU](https://huggingface.co/docs/hub/spaces-zerogpu#usage-tiers) указывает для неавторизованных посетителей **2 минуты GPU в сутки**, низкий приоритет и восстановление квоты через 24 часа после первого использования. Это не две минуты ожидания и не фиксированное количество сообщений. Условия могут измениться.

**Квота общая для демо.** Смена модели её не обнуляет. Демо заранее запрашивает резерв GPU: Gemma 3/3n — 120 секунд, Gemma 2/Llama — 90 секунд, Mistral — 60 секунд. Поэтому при частично потраченной квоте даже простой вопрос может не запуститься; для Gemma 3/3n возможен всего один запуск до восстановления квоты. Автовыбор не пытается обойти эти ограничения перебором новых демо.

1. Выберите модель в чате и прочитайте её описание/возможности.
2. Лучше начать с одного рабочего вопроса или фото, **без лишней проверки**. В настройках ИИ есть **«Проверить соединение»**, но она тоже запускает генерацию и **расходует квоту**: для Gemma 3/3n после проверки может не хватить остатка на само задание. Проверка не обязательна и не резервирует будущий доступ; не проверяйте все модели подряд.
3. При исчерпании квоты или требовании входа приложение покажет ошибку, а не выдаст её за ответ. Дождитесь восстановления доступа. Внешний аккаунт, API-ключ и оплата автоматически не подключаются.
4. Очередь/генерация ожидаются до **5 минут**. «Остановить» прекращает ожидание; удалённый сервер мог уже потратить GPU-время. Автоматического повтора нет.
5. У текстовых демо небольшой контекст. Если история/задание слишком длинные, начните новый диалог или разделите работу. Условие не обрезается незаметно; ответы ограничены по длине, при необходимости попросите продолжить вручную.

Демо может спать, перегружаться, изменять API или перестать принимать анонимные запросы. Успешное чтение описания/каталога **не гарантирует генерацию**. В 4.1 проверены опубликованные исходники и контракты API, но живые генерация, анонимная квота и загрузка фото из среды разработки не проверены. [Подробные источники и способы проверки](docs/PUBLIC_DEMOS.md).

**На iPhone HTML Viewer:** новые модели не отменяют ограничения WebView/CORS. Сообщение «Не удалось связаться с публичным демо» может означать запрет внешнего запроса, а не отсутствие модели. При проблеме попробуйте тот же HTML в поддерживаемом браузере или HTTPS-версию в Safari. Не обходите авторизацию/квоты. На физическом iPhone работу новых демо ещё нужно проверить.

Задание, текст текущего диалога и фото отправляются владельцу выбранного Space. В карточке есть ссылка на площадку; Mistral работает в демо **hysts**, не через официальный API Mistral. Не отправляйте ФИО, лица, адреса и другие личные сведения. Локальный семейный аккаунт в приложении не является аккаунтом внешнего сервиса.

Это публичные внешние сервисы, а не встроенная в HTML нейросеть. Работа без ключа, очереди и бесплатные лимиты могут изменяться. При полном отсутствии связи автовыбор для текста/OCR может дать ограниченный локальный ответ; это не результат облачной модели. В детском режиме такой ответ остаётся учебной подсказкой. **При передаче самого изображения** ошибки Vision не подменяются локальным ответом или OCR.

Под выбором модели — краткое описание и цветные кружки: **фиолетовые — мощность, зелёные — скорость, голубые — понимание**. Это **условные редакционные ориентиры 1–5, не замеры и не бенчмарк**. Для автовыбора/маршрутизатора оценка меняется, для неизвестной или локальной модели честно показано отсутствие сопоставимой оценки. Пустые кружки не означают нулевой интеллект. Сравнение бесплатных вариантов раскрывается под списком; у других провайдеров карточка показана в настройках.

2. Перейдите по **«Получить ключ»** в настройках, создайте ключ в своём аккаунте OpenRouter и вставьте его в поле приложения. Не присылайте ключ в чаты и не публикуйте его в репозитории.
3. Обновите список бесплатных моделей кнопкой обновления каталога.

5. Для снимков обратите внимание на обозначение поддержки фото/Vision. У текстовой модели фото сначала проходит отдельное распознавание.
6. Проверьте соединение и сохраните настройки.

**Бесплатная модель не означает отсутствие аккаунта, ключа или лимитов.** Недоступный каталог заменяется сохранённым/встроенным списком с предупреждением; это не подтверждение, что каждая перечисленная модель сейчас работает. Ошибку отсутствующего ключа приложение не скрывает переходом к другому провайдеру.

### Ollama / свой API: два способа подключения

Ollama — **отдельная программа на вашем компьютере**, а не модель внутри HTML. Приложение не устанавливает её и не загружает модели автоматически. В терминале компьютера сначала проверьте:

```text
ollama list
ollama run qwen2.5:7b
```

`qwen2.5:7b` — пример текстовой модели. Используйте точное имя из `ollama list`. Если модели нет, предварительно установите её через `ollama pull ИМЯ_МОДЕЛИ`; загрузка может занимать гигабайты, а скорость зависит от памяти и оборудования. Первый ответ часто медленнее последующих. Для фото нужна именно **мультимодальная Vision-модель**, а не просто модель с похожим названием.

#### Вариант А. Через свой Python-сервер — удобнее для телефона

1. Подготовьте серверную версию по [разделу 14](#server): исходники, зависимости, `npm run build`. Это **не** `python -m http.server` в папке с одним HTML.
2. Оставьте Ollama запущенной на том же компьютере с обычным адресом `127.0.0.1:11434`. Не требуется открывать порт Ollama в интернет или менять её адрес на `0.0.0.0`.
3. Остановите ранее запущенный `server.py` и включите мост **в том же терминале, из которого запускаете Python**:

**Windows PowerShell:**

```powershell
$env:DOMASHKA_ENABLE_OLLAMA_PROXY="1"
# Необязательно: это уже адрес по умолчанию
$env:DOMASHKA_OLLAMA_URL="http://127.0.0.1:11434/v1"
.venv\Scripts\python server.py
```

**macOS / Linux:**

```bash
DOMASHKA_ENABLE_OLLAMA_PROXY=1 .venv/bin/python server.py
```

Если Ollama намеренно находится на другом доверенном сервере, владелец задаёт `DOMASHKA_OLLAMA_URL` перед запуском. Поддерживаются корень API, `/v1` или полный `/v1/chat/completions`. Адрес нельзя передать браузерным запросом; редиректы и системный HTTP-прокси для этого соединения отключены. Файл `.env` автоматически не загружается.

4. На компьютере откройте **`http://localhost:8000`**. На телефоне в той же доверенной Wi-Fi-сети — адрес **компьютера**, например `http://192.168.1.25:8000`, если именно такой IP показан у вашего ПК. В Windows IP можно посмотреть через `ipconfig`; разрешите Python в брандмауэре только для частной сети.
5. В шестерёнке ИИ выберите **«Ollama / свой API» → «Через мой Python-сервер (Ollama)»**. Введите имя установленной модели. URL и API-ключ прямого подключения здесь не используются.
6. Нажмите **«Проверить соединение»**, дождитесь ответа и сохраните настройки. Python обращается к своей Ollama; телефон не обращается к собственному `localhost` и не делает прямой CORS-запрос к Ollama. Ожидание модели — до 120 секунд, клиент ждёт сервер чуть дольше; проверку можно отменить.

**Границы этого варианта:**

- Мост по умолчанию **выключен**. Он не работает в `Domashka_PRO.html`, HTML Viewer или GitHub Pages — даже если просто отдать готовый автономный HTML через веб-сервер. Нужны `server.py` и его серверная сборка из `static/`.
- Страница и `/api/ai-generate` должны иметь один origin. Браузерные запросы с постороннего сайта и `Origin: null` отклоняются. Проверка Origin/Host — **не авторизация**; клиент командной строки в доверенной сети может обращаться без Origin.
- Это домашний сервер без учётных записей и квот, **не публичный прокси**. Не пробрасывайте порты роутера и не публикуйте его в интернет. Для удалённого доступа нужны отдельная авторизация, ограничения нагрузки и HTTPS.
- HTTP по IP в домашней сети подходит для проверки текстового ИИ, но **не гарантирует** Web Crypto/родительский пароль, голос и камеру. На iPhone прямой вызов камеры в таком контексте отключён. Для этих функций нужен доверенный HTTPS, либо снимок обычной «Камерой» и диктовка клавиатуры. Настройка доверенного HTTPS для домашнего сервера — отдельная задача; она не появляется автоматически при запуске Python.

#### Вариант Б. Напрямую из браузера

Выберите **«Напрямую из этого браузера»**, укажите доступный адрес API и точное имя модели. Для стандартной Ollama ключ обычно не нужен. Варианты `http://localhost:11434`, `http://localhost:11434/v1` и полный `http://localhost:11434/v1/chat/completions` приводятся к правильному OpenAI-совместимому endpoint. **`/api/chat` и `/api/generate` — другой, нативный API Ollama; сюда их вводить не нужно.**

При прямом соединении:

- `localhost` / `127.0.0.1` на iPhone — **сам iPhone**, а не компьютер. Если Ollama работает на ПК, нужен доступный адрес ПК или вариант А.
- Ollama должна разрешать **конкретный origin страницы** через `OLLAMA_ORIGINS`, после изменения её надо полностью перезапустить. Например, для страницы `http://localhost:8000` origin именно `http://localhost:8000`; для GitHub Pages origin не содержит `/Domashka.PRO/`. Не разрешайте `*` и не отключайте защиту браузера.
- Локальный HTML часто имеет origin `null`; это не уникальный доверенный сайт. Вместо широкого разрешения для всех локальных файлов лучше использовать серверный вариант.
- HTTPS-страница обычно блокирует HTTP API другого компьютера как смешанное содержимое. Разрешение CORS **не исправляет** это: нужны HTTPS API или серверный мост. Доступ к локальной сети также может ограничиваться браузером/ОС.
- HTML Viewer может блокировать HTTP/локальную сеть на уровне iOS-приложения. Проверьте разрешение «Локальная сеть», если оно доступно, либо смените способ запуска. JavaScript не может отменить ограничения приложения.

`Failed to fetch` / `Load failed` — общий сетевой отказ, **не доказательство одной причины**. Теперь приложение показывает адресные подсказки, но не может из такого сообщения отличить CORS, выключенную Ollama, неверный IP, брандмауэр или запрет iOS. HTTP 404 обычно требует проверить имя установленной модели и endpoint; таймаут — загрузку модели и ресурсы ПК. Успешная текстовая проверка связи ещё **не проверяет Vision**: отправьте отдельное тестовое изображение.

#### Фото с Ollama

Включайте **«Моя модель поддерживает изображения (Vision)»** только для действительно мультимодальной модели и совместимого сервера. Галочка не добавляет зрение текстовой модели. Затем выберите способ **«Само фото (Vision), без подмены на OCR»** в задании. Отправляются сами изображения в формате OpenAI `image_url`, до четырёх за запрос; фактические ограничения вашей модели могут быть строже — при отказе будет ошибка, а не незаметная подмена.

В **«Авто»** для Ollama без Vision автоматической отправки снимков в облачный OCR **нет**: нужно явно выбрать OCR или настроить Vision. Режим OCR и отдельная кнопка **«Прочитать текст с фото»** могут передавать фото сторонним сервисам. Поэтому выбор Ollama сам по себе не делает все функции приложения офлайн. Голос тоже обрабатывается отдельным сервисом браузера/ОС, не Ollama.

## 7. Задание: текст, фото, документы и диалог

### Ввести текст

1. Откройте главный раздел **«Решить»**; в детском режиме он называется **«Репетитор»**.
2. Выберите предмет или **«Автоопределение»**. Дополнительные предметы находятся в списке **«Ещё предметы…»**.
3. В обычном режиме выберите формат:
   - **«Как в тетрадь (ФГОС)»** — оформленная запись;
   - **«Пошаговый разбор»** — объяснение решения;
   - **«Репетитор (без спойлеров)»** — подсказки и учебный диалог;
   - **«Сочинение / Конспект / Таблица»** — работа с текстом.
4. Вставьте полное условие: данные, единицы измерения, ограничения, что требуется найти. Добавьте свою попытку и место затруднения.
5. Отправьте задание. В детском режиме кнопка называется **«Начать с подсказки»**.
6. Дождитесь ответа. Если нужно прервать работу, нажмите кнопку остановки/отмены; повторно нажимать отправку много раз не нужно.
7. Продолжайте в поле диалога под ответом: задайте уточнение либо отправьте свой следующий шаг.

Пример для репетитора:

> «Я в 6 классе. Решаю 3x + 7 = 22. Думаю, сначала нужно убрать 7 из левой части. Проверь мой следующий шаг, не говори готовый ответ».

Обычный выбор формата «Репетитор» не запаролен: переключиться на другой формат можно. Если ребёнок не должен переключать формат, нужен **детский режим** из раздела 8.

### Фото задания

1. На совместимом телефоне можно нажать **«Камера»**, на ПК — **«Загрузить фото»**. Для HTML Viewer/iPhone используйте обычную «Камеру» и затем **«Галерею»**, как описано выше. На ПК работает вставка изображения из буфера (`Win + Shift + S` → `Ctrl + V`), если браузер её разрешает.
2. Можно прикрепить **до 4 фото**, но лимит передачи **самих изображений** зависит от выбранной модели — см. таблицу ниже. Сохраняйте порядок страниц; снимки можно переставлять и удалять.
3. В поле **«Как передать фото нейросети»** выберите:
   - **«Авто»** — изображение передаётся напрямую, если модель и число снимков подходят; иначе для облачных моделей используется OCR. Для Ollama без Vision OCR нужно разрешить отдельным явным выбором.
   - **«Само фото (Vision), без подмены на OCR»** — нейросеть получает реальные байты изображения: может рассматривать схему, график, геометрическую фигуру и пространственные связи, а не только буквы. При несовместимости, лишних снимках или ошибке сервиса появится ошибка; скрытого перехода на OCR/локальную подсказку нет.
   - **«Только распознанный текст (OCR)»** — отдельный распознаватель извлекает текст, а ответная модель получает текст, **не рисунок**. Схемы и взаимное положение объектов могут потеряться. Отдельная кнопка «Прочитать текст с фото» тоже означает OCR; в строгом Vision она отключена до явного переключения режима.
4. При необходимости обрежьте фото до нужной задачи, поверните, выберите фильтр. Для цветных схем лучше **«Оригинал»**. Проверьте резкость степеней, дробей и знаков.
5. Укажите номер задания, если на странице их несколько, дождитесь подготовки фото и отправьте запрос. Отдельно запускать OCR перед Vision **не нужно**.

| Провайдер / модель | Передача самого изображения |
|---|---|
| Бесплатный Qwen 3.5 Omni / Qwen 2.5 VL | **1 фото**; отправляется реальный снимок через файловую загрузку шлюза |
| Google Gemma 3 12B / Gemma 3n E4B · демо | **1 фото JPG/PNG/WebP** напрямую, через загрузку в выбранный Space |
| Google Gemma 2 9B / Meta Llama 3.2 3B / Mistral 7B · демо | Только текст; фото — через выбранный OCR |
| Бесплатный «Автовыбор» | **1 фото**; перебираются только совместимые Qwen-шлюзы, без Pollinations и локального ответа |
| Pollinations | Текстовый маршрут; для фото — явно выбранный или автоматический OCR |
| Gemini | До **4 фото** в одном запросе |
| OpenRouter | До **4 фото**, если для модели указана поддержка Vision; каталог/доступность может меняться |
| Ollama / свой API | До **4 фото** только с включённой поддержкой Vision; модель/сервер могут иметь более строгие ограничения |

При двух–четырёх фото с бесплатным шлюзом **«Авто» использует OCR**; строгий Vision попросит оставить один снимок или выбрать подходящего провайдера. Не считайте четыре прикреплённых фото доказательством, что каждый шлюз принимает четыре изображения.

Над результатом показано **«ИИ получил само изображение (Vision)»** либо **«ИИ получил распознанный текст (OCR)»**. Для диалога, начатого с Vision, **все его изображения сохраняются в истории и повторно передаются в уточняющих вопросах**. Если переключить такой диалог на текстовую модель, будет сообщение о несовместимости, а не незаметная потеря рисунка. Выбранный способ обработки сохраняется вместе с чатом и в резервной копии; изменить способ для нового решения можно в форме задания.

Один исходный файл — до **18 МБ**. Снимок уменьшается до 1650 пикселей по длинной стороне без хранения полноразмерной base64-копии; временные URL и canvas освобождаются. Это снижает расход памяти, но не гарантирует работу огромных 48 Мп/ProRAW в любом WebView. При ошибке HEIC сохраните JPG/PNG; приложите отдельный крупный фрагмент, если после уменьшения детали мелкие. Ограничение API — до 20 МБ суммарных закодированных изображений.

Не загружайте ФИО, адреса, лица детей и другие ненужные личные данные. В облачном Vision снимки уходят выбранному провайдеру. OCR может использовать отдельные сторонние сервисы, **даже при выбранной Ollama**. Понимание схемы не гарантируется одним фактом передачи изображения: просите модель перечислить видимые объекты и проверяйте её выводы.

### Документы, голос и рисунки

- Кнопка документа принимает **DOCX, PDF, TXT, MD и CSV**. Старый `.doc` сначала сохраните как `.docx` или текст.
- Для PDF основной обработчик читает **до 6 первых страниц с чтением текстового слоя**. Для PDF-скана распознаётся **первая страница**, а не весь многостраничный документ. Для задания на другой странице сделайте отдельный снимок. Загрузка PDF-библиотеки и OCR могут потребовать интернет; часть простых документов обрабатывается локально.
- Кнопка **«Нарисовать»** позволяет добавить формулу или схему; аккуратный текст/снимок обычно надёжнее сложного рисунка.
- Голосовой ввод описан ниже. Озвучивание готового ответа — другая функция, оно не распознаёт вашу речь.

### Голосовой ввод на телефоне

1. Откройте сайт по **HTTPS** в обычной вкладке Safari на iPhone либо в совместимом мобильном браузере (например, Chrome на Android).
2. Рядом с полем задания/работы нажмите **«Голосом»**, разрешите микрофон/распознавание, если браузер спрашивает, и произнесите короткую фразу.
3. Промежуточный текст виден как предпросмотр, подтверждённые фразы добавляются в поле без повторов. Кнопка **«Слушаю… (стоп)»** завершает запись и даёт браузеру вернуть последнюю фразу. При уходе со страницы/раздела или блокировке поля запись прерывается, без автоматического повторного запуска.
4. Проверьте полученный текст и **отправьте его вручную**. Особенно проверяйте формулы: речь может превратить «икс в квадрате» в обычные слова.

Используются Web Speech `SpeechRecognition` / `webkitSpeechRecognition`, **если они доступны**. Версия ОС, язык, сеть, разрешения, Siri/системная диктовка и правила WebView могут влиять на работу. Аудио обрабатывает сервис браузера/ОС, часто сетевой, **не выбранная нейросеть и не Ollama**. Полностью офлайн-распознавание и работа во всех мобильных браузерах не обещаются.

В локальном iOS HTML Viewer опасный вызов микрофона отключён. При отсутствии API, запрете разрешения, сетевой ошибке или зависшем запуске появляется подсказка, а не ложное сообщение об успешном распознавании.

**Запасной способ для телефона:** нажмите на текстовое поле → микрофон **экранной клавиатуры**. На iPhone проверьте **Настройки → Основные → Клавиатура → Включить диктовку**; на Android — диктовку используемой клавиатуры. Это функция ОС, а не гарантия распознавания кнопкой сайта. Если микрофона нет и там, остаётся ввод текста/фото и проверка настроек устройства. Реальные разрешения iOS/Android и работа сервиса речи на вашем устройстве требуют проверки — тесты проекта используют подставной Speech API.

### OpenRouter, публичные демо, ожидание и проценты этапов

Ранее общий браузерный тайм-аут OpenRouter составлял 22 секунды. В 4.0 прямой запрос ожидает до **5 минут**, читает поток SSE с ответом и не завершает ожидание только потому, что пришли HTTP-заголовки. В старом WebView поток может стать доступен лишь целиком. Серверный путь также получил увеличенный лимит; клиент ждёт сервер немного дольше. Кнопка **«Стоп»** остаётся доступной.

В 4.1 новые публичные демо также имеют **единое пяти­минутное ожидание**: фото, очередь и весь ответ. Промежуточный текст/heartbeat не считаются завершением; при обрыве неполный ответ не сохраняется. После ошибки Python-сервера запрос не повторяется напрямую в браузере. Отмена ожидания не обещает возврат квоты площадки.

Отдельно показаны подготовка условия, подготовка/OCR фото, получение ответа и обработка/сохранение. **100% и галочка появляются по факту завершения этапа**, а не после фиксированных 2–6 секунд. У фото учитывается обработка страниц; при Vision подготовка фото не означает, что модель уже поняла рисунок — это происходит вместе с генерацией ответа.

**≈ — оценочное ожидание, не процент внутренней работы нейросети.** OpenRouter не сообщает такой процент. Оценка может долго оставаться около 90%, если провайдер продолжает работу; это не обещание конкретного времени окончания. При потоковой передаче дополнительно показывается число полученных символов. Пауза бесплатного канала означает время до следующей попытки, не до готового ответа.

Ошибки ключа, запрета доступа/региона, баланса, квоты и недоступности модели различаются. Оборванный поток без завершения не сохраняется как готовое решение; остановка по лимиту токенов отмечается предупреждением в тексте. После неопределённого серверного сбоя **не запускается автоматически второй платный запрос** напрямую. Отмена браузером не гарантирует остановку вычисления или списания у провайдера — перед повтором проверьте его журнал.

Дополнительные непроверенные названия моделей в бесплатный встроенный канал не добавлялись. Сохранён существующий набор Qwen/Pollinations и автовыбор; наличие внешних шлюзов, квоты и скорость не гарантируются. Для другого каталога используйте доступные модели выбранного провайдера с собственным ключом.

### Сохранить полученный ответ

В блоке результата доступны средства копирования, выгрузки текста, Word/DOCX, изображения тетрадного листа и печати. Для PDF выберите **«Печать» → «Сохранить как PDF»**, если такой пункт предлагает ОС/браузер. Некоторые кнопки зависят от раздела и размера экрана.

Озвучивание использует голоса, доступные браузеру/системе. Если нет русского голоса или функция недоступна, ответ остаётся доступен текстом. Экспорт и озвучивание не заменяют резервную копию всей истории.

## 8. Семейные аккаунты 4.0: инструкция родителю

### Сначала проверьте ограничения

Это **локальные аккаунты одного браузера/HTML Viewer**, а не регистрация на сервере. Семейный кабинет, логины, задания и ответы не синхронизируются между ПК и телефоном. Даже один HTTPS-адрес на двух устройствах не создаёт общей семейной базы. Для задания и проверки работы на одном устройстве переключайте аккаунты; удалённого семейного сервиса в этой версии нет.

- Требуются постоянное `localStorage`, `sessionStorage` и **Web Crypto**. Предпочтительны HTTPS либо локальный HTML в поддерживаемом браузере. Обычный HTTP по адресу ПК в сети может не предоставлять криптографию для паролей.
- На iPhone **HTML Viewer проверьте отдельно**: создайте тестовый аккаунт, выйдите, закройте приложение просмотра, откройте тот же файл и войдите снова. Если криптография или хранение недоступны, появится ошибка, а не фиктивно сохранённый аккаунт. Совместимость конкретного Viewer не гарантируется; запасной путь — Safari HTTPS. Физический iPhone для проверки не использовался.
- Каждый аккаунт имеет отдельные чаты/фото, черновики, закладки, дневник, расписание, статистику и настройки ИИ. Родитель видит семейную домашку и учебную сводку привязанных детей, **не список их личных чатов в семейном кабинете**.
- Пароли хранятся в виде PBKDF2-SHA256-хешей с индивидуальной солью, а не открытым текстом. Однако **учебные данные и API-ключи на устройстве не зашифрованы**. Это разделение интерфейса, не защита от владельца файлов браузера, инструментов разработчика, очистки данных или нового браузерного профиля.
- Корень вроде **√49 — формальный вопрос, не проверка возраста или доказательство родительства**. Настраивайте первую семью сами, храните пароль отдельно и выходите перед передачей устройства ребёнку.

### Создать первую семью

1. Откройте **«Семья»** или **«Настроить»** в полоске аккаунта под шапкой.
2. Введите имя и уникальный логин (3–32 буквы/цифры, также точка, дефис, подчёркивание; без пробелов). Регистр логина не важен.
3. Задайте и повторите пароль: **8–128 символов**. Не используйте пароль от других важных сервисов.
4. Выберите аватар-значок либо загрузите свою картинку. Она уменьшается до 128 пикселей и остаётся локально.
5. Решите показанный математический вопрос. Если ранее был настроен старый детский режим, дополнительно требуется **его действующий родительский пароль** — создать новый аккаунт для обхода защиты нельзя.
6. Нажмите **«Создать семью и войти»**. Страница перезагрузится; откроется семейный кабинет.
7. После появления семейной базы свободного гостевого входа больше нет. Старые данные версии 3.x при этом **не удаляются**.

В приложении можно создать до 40 аккаунтов. Новые аккаунты после первого добавляет только вошедший родитель. Логин существующего аккаунта не переименовывается; отображаемое имя и аватар можно менять.

### Добавить ребёнка и выбрать ограничения

1. Откройте **«Добавить ребёнка или родителя»**, выберите тип **«Ребёнок»**.
2. Введите имя, отдельный логин и пароль с подтверждением, выберите аватар, **класс 1–11** и **возраст 5–21**. Возраст — учётная информация; подборка и учебный стиль прежде всего ориентируются на класс.
3. Создайте аккаунт. Ребёнок автоматически привязан к вам; ваш сеанс не переключается на его аккаунт.
4. Выберите ученика слева (на телефоне список расположен сверху) и откройте **«Настройки ученика и родительский контроль»**.
5. Настройте:
   - **Только репетитор** — короткие подсказки вместо готового чистовика, без проверяющего и решающих калькуляторов. По умолчанию включено.
   - **Разрешить ИИ и распознавание фото** — если выключено, новые запросы ИИ и OCR блокируются, но дневник, локальные материалы и отправка семейной работы доступны. Это не отключает интернет устройства или системную диктовку ОС.
   - **Использовать мои текущие настройки ИИ** — необязательная передача выбранного провайдера/модели и ключа родителя. Без неё у ученика отдельные настройки, по умолчанию бесплатный канал. Ключ используется в браузере и не может быть надёжно скрыт от его владельца; бюджет ключа ограничивайте у провайдера.
   - **Заблокировать вход** — закрывает доступ ученика без удаления его данных.
6. Сохраните ограничения. Открытые сеансы ребёнка отзываются; нужно войти заново. Незавершённые ИИ/OCR-запросы перестают ожидаться и не должны записаться в чужую тетрадь.

Класс и настройки ИИ ребёнок самостоятельно не меняет, даже если разрешён обычный режим решений. В семейном аккаунте щит/кнопка настроек ведёт к объяснению управления через родителя, а не к установке нового обходного пароля.

### Ещё один родитель и привязка существующего ребёнка

- В разделе добавления выберите **«Ещё один родитель»**, задайте его логин/пароль, решите вопрос и подтвердите действие **вашим текущим родительским паролем**.
- Создание второго родителя не даёт ему автоматически всех детей.
- Текущий родитель выбирает ребёнка → настройки → **«Создать код привязки»**. Код одноразовый, действует **15 минут**.
- Выйдите, войдите под другим родителем и введите код в **«Код от другого родителя»**. Оба родителя смогут назначать и проверять работы этого ребёнка.
- Код работает только в той же локальной базе, не связывает разные устройства или браузеры.
- Связь можно отозвать в настройках ребёнка. У него должен оставаться хотя бы один родитель. Снятие связи прекращает доступ этого родителя к заданиям и сводке ученика.

### Задать, сдать и проверить домашку

1. **Родитель:** выберите ребёнка, заполните предмет, название, условие и, при необходимости, дату → **«Назначить домашку»**.
2. Нажмите выход в полоске аккаунта, подтвердите, затем войдите под логином ребёнка.
3. **Ребёнок:** откройте **«Семья» → «Домашка от родителей»**. Первые работы также видны в **«Дневнике»**.
4. Напишите ответ или приложите **одну фотографию** → **«Отправить родителю»**. Фото уменьшается до 1280 пикселей; размер закодированного вложения ограничен. Оно сохраняется локально и **не отправляется ИИ** самим действием сдачи.
5. Статус меняется на **«Ждёт проверки»**. До принятия можно обновить отправку. При повторной отправке прежнее фото сохраняется, если не выбрать удаление или новое фото.
6. **Родитель:** снова войдите в свой аккаунт, откройте работу. При наличии вложения нажмите **«Показать фото работы»**. Просмотр фотографий сделан по запросу, чтобы не загружать сразу всю фотобазу в память телефона.
7. Напишите комментарий, при желании оценку 1–5 и нажмите **«Принять»** либо **«На доработку»**. Для доработки нужен комментарий. Это **ручная родительская проверка**, не обещание безошибочной оценки ИИ.
8. Ребёнок видит отзыв, исправляет решение и отправляет новую попытку. Принятую работу сначала должен вернуть на доработку родитель, если нужно её изменить.

Семейная оценка **не добавляется автоматически в школьные отметки**. Галочка в личном планере ребёнка тоже не означает принятие родителем. Учебная сводка показывает локальные счётчики и введённые отметки, а не данные школьного электронного журнала.

В списке есть фильтры статусов и страницы по 8 работ (в дневнике — первые 3). **«Скачать показанные работы (JSON)»** сохраняет текущую страницу вместе с ответами, фото и отзывами для отдельного хранения/чтения. Это не перенос аккаунтов и не автоматический импорт семейной базы. Для большой базы выгружайте страницы отдельно; через API экспорт ограничен 50 работами за раз. Родитель может явно удалить работу с подтверждением — вместе с её ответом и фото.

Текст неотправленного ответа сохраняется как отдельный черновик текущего аккаунта. **Новое неотправленное фото после смены аккаунта нужно выбрать заново**. При ошибке сохранения не закрывайте форму: освободите место или повторите действие. Если IndexedDB изначально недоступна, семейные работы используют ограниченное localStorage с предупреждением; если уже выбранная IndexedDB временно отказала, приложение не заменяет её пустой базой.

### Смена аккаунта, пароля и старые данные

- Выход находится в полоске аккаунта под шапкой. Выход отзывает все сеансы **этого аккаунта**, а не всех членов семьи. Сеанс также ограничен восемью часами; пароль и блокировка отзывают старые сеансы.
- Смена аккаунта выполняется с **перезагрузкой страницы**. Это намеренно: поздний ответ, голосовой ввод или сохранение старого компонента не должны оказаться у другого пользователя.
- Имя, аватар и собственный пароль меняются в **«Мой аккаунт»**. Для нового пароля нужен текущий и подтверждение нового.
- Родитель может сменить пароль своего ребёнка, подтвердив своим паролем. **Восстановления забытого родительского пароля по почте нет**; другой родитель не может просто сбросить его. Сохраните пароль в надёжном месте.
- Первый создавший семью родитель получает раздел **«Старые данные версии 3.x»**. Выберите свой аккаунт либо своего ребёнка и запустите копирование. Переносятся тетрадь/фото, дневник, расписание, закладки, статистика и часть настроек; ключи ИИ, пароли и сеансы не копируются. Оригиналы остаются, совпадающие чаты и уже заполненные настройки не перезаписываются. Повторный запуск не должен создавать дубликаты чатов.
- После копирования войдите в выбранный аккаунт заново. Данные другого браузера, URL или другого экземпляра Viewer автоматически недоступны.
- JSON тетради сохраняет **чаты одного аккаунта**, не всю семью. Для семейных работ используется отдельная выгрузка. Полного переносимого бэкапа логинов, паролей, настроек и связей в 4.0 нет; не очищайте профиль браузера и не считайте HTML-файл резервной копией данных.

### Старый одно-профильный детский режим (без семейного аккаунта)

Эта настройка сохранена для прежнего сценария использования. Для аккаунтов детей используйте семейный кабинет выше; их ограничения нельзя снять этой формой.

### Включить

1. Сначала настройте класс и нейросеть. Проверьте соединение и попробуйте одно задание.
2. При необходимости сохраните копию обычной истории.
3. Нажмите **щит/замок** в шапке.
4. Придумайте и повторите родительский пароль: **8–128 символов**. Не используйте пароль от почты, банка или других важных сервисов. Сохраните его у себя.
5. Нажмите **«Включить детский режим»**.
6. Убедитесь, что появилась зелёная плашка **«Детский режим: только репетитор»**.
7. Перезагрузите страницу, затем закройте и снова откройте приложение обычным способом ребёнка. Проверьте, что режим сохранился.

### Что меняется

- Главный раздел работает как репетитор: инструкции модели требуют коротких подсказок, одной следующей задачи/вопроса и самостоятельной попытки ученика.
- Доступны репетитор, семья, дневник и справочные материалы.
- Скрываются готовые форматы решений, проверяющий, калькуляторы решений, ИИ-тесты, общие импорт/экспорт и свободное изменение ИИ-настроек.
- Обычные чаты **не удаляются**, но скрываются. Во время блокировки показываются учебные диалоги, созданные в этом режиме.
- Локальный запасной ответ также не подставляет полное решение.

### Отключить или изменить пароль

Нажмите замок либо **«Для родителей»**, введите действующий пароль и нажмите **«Отключить детский режим»**. Для замены используйте **«Изменить родительский пароль»**, текущий пароль и подтверждение нового. После нескольких неверных попыток применяется временная задержка.

**Ограничения, которые важно понимать:**

- Пароль хранится как хеш с солью и не отправляется ИИ, но это **локальная защита интерфейса**, а не защита всего устройства или серверный аккаунт.
- Она не переносится автоматически на другой браузер, устройство, URL, приватный профиль или новую область хранения. На телефоне её нужно настроить отдельно.
- Очистка данных, изменение кода/хранилища или другой браузер могут обойти режим.
- Генеративная модель способна нарушить инструкции и выдать ответ. Нельзя гарантировать отсутствие спойлеров только системным промптом.
- Восстановления забытого пароля нет. Очистка данных может привести также к потере истории и других настроек; не используйте её как первый способ решения любой ошибки.
- Для сохранения режима нужны постоянное хранилище и Web Crypto. HTTPS — предпочтительный вариант. На обычном HTTP по адресу компьютера в домашней сети Web Crypto может быть недоступен.

### До 9 уроков и каждая перемена отдельно

В **«Дневнике» → расписании** задайте начало первого урока, длительность урока и **количество уроков от 1 до 9**. Прежние 7-позиционные расписания сохраняют записи и получают дополнительные пустые позиции. У новых аккаунтов расписание и личный планер начинают работу без чужих демонстрационных заданий.

### Шпаргалки и строгий фильтр класса

В 4.0 **1263 уникальные карточки, включая 563 новые**. По согласованному объёму обеспечено **не менее 25 карточек всего** в каждой из **106 пар «класс — предмет»** справочного набора. Это не 25 новых сверх старых и не одинаковый искусственный набор предметов для первого и одиннадцатого классов. [Полная таблица покрытия](REFERENCE_COVERAGE.md).

При открытии выбран **«Мой класс»** из профиля. Есть отдельные кнопки 1–11, все классы и закладки. Карточка попадает в класс, только если её явный диапазон включает этот класс. Общая тема для соседних лет хранится один раз и помечена диапазоном. Поэтому сумма чисел по классам больше числа уникальных карточек базы.

Поиск также соблюдает предмет и класс. При нулевом результате он **не показывает тайно другие классы**: можно изменить фильтры либо явно нажать **«Искать по всем классам и предметам»**. Закладки изолированы по аккаунтам.

Диапазоны справочника — не утверждение о текущем обязательном учебном плане любой школы; начало отдельных предметов и проектная работа зависят от программы. Материалы и экзаменационные нормы сверяйте с учителем. В старой базе точечно уточнены только уверенно исправляемые математические условия; независимая экспертиза всей базы не заявляется.

### Тренажёр, калькуляторы, справочник

Выберите предмет, тему и подходящий вид занятия. Не каждая тренировка офлайн: создание новых материалов с помощью ИИ требует работающего провайдера. Калькуляторы поддерживают свои конкретные форматы ввода, а не любую произвольную задачу. При переносе задания из справочника к ИИ текст отправляется внешнему сервису.

В детском режиме часть переходов отсутствует или направляет к репетитору — это ограничение режима, а не поломка навигации.

<a id="backup"></a>
## 10. История, резервная копия и перенос

### Найти сохранённый диалог

На ПК используйте левую панель **«Чаты»**, на телефоне — значок диалога вверху. Откройте нужную запись; можно продолжить обсуждение. В панели есть управление названиями, избранным и удалением. Новый чат создаётся соответствующей кнопкой, чтобы не смешивать разные задания.

### Создать копию истории

1. В обычном профиле родитель при необходимости временно отключает детский режим паролем. Для семейного ученика родитель временно меняет ограничение в кабинете и затем входит под учеником; экспорт родительской тетради не выгружает тетрадь ребёнка.
2. Откройте панель чатов.
3. Внизу нажмите **«Скачать копию»**.
4. Сохраните файл вида `Domashka_PRO_Chats_ГГГГ-ММ-ДД.json` в надёжном месте.
5. Если режим был отключён, включите его снова.

В семейной версии экспорт относится **только к текущему аккаунту**. Семейные работы выгружаются отдельно из кабинета; логины, хеши паролей и связи в экспорт тетради не входят.

Это **копия чатов**, включая сохранённое содержимое диалогов и прикреплённые изображения, **а не полный бэкап приложения**. Она не переносит дневник/расписание, настройки ИИ, API-ключи и родительский пароль. При переполнении хранилища часть данных могла не сохраниться; экспорт не может восстановить отсутствующее.

Для важных записей дневника храните дополнительную копию отдельно. Не публикуйте JSON чатов: в нём могут быть тексты заданий и фото.

### Перенести чаты на другое устройство

1. Передайте свой JSON безопасным способом на другое устройство.
2. Откройте приложение на нём, вне детского режима.
3. В панели чатов нажмите **«Загрузить»** и выберите JSON.
4. Проверьте импортированные записи. Импортированные метки детского режима не считаются доверенными; импорт не переносит родительскую защиту.
5. Отдельно выберите класс, настройте ИИ и при необходимости включите детский режим на новом устройстве.

ПК и телефон **не синхронизируются автоматически**, даже при одном адресе сайта. Если из локального файла перейти на HTTPS, это также новая область данных. Не удаляйте старую копию до успешного переноса.

## 11. Интернет, хранение и приватность

| Возможность | Зависимость от интернета |
|---|---|
| Запуск скачанного HTML на совместимом браузере | Основной интерфейс, стили и математические шрифты уже встроены |
| Запуск сайта по HTTPS | Для первой загрузки и гарантированного повторного открытия нужен интернет; специального офлайн-кеша нет |
| Справочник, локальные калькуляторы, дневник, сохранённая история | Работают локально после загрузки приложения, если браузер разрешает хранение |
| Ответы облачного ИИ, проверка, генерация новых ИИ-материалов | Нужны интернет, доступный сервис, иногда ключ и свободная квота |
| Фото/OCR и PDF | Зависят от конкретного пути обработки; внешние запросы и загрузка дополнительных компонентов возможны |
| Голос | Зависит от браузера, ОС, разрешений и иногда сети |

Чаты и фото сохраняются преимущественно в IndexedDB, настройки/дневник — в localStorage. Семейные аккаунты/хеши/связи находятся в общем локальном реестре, текущий сеанс — в sessionStorage с проверкой реестра; личные хранилища разделены по идентификаторам аккаунтов. Семейные работы имеют отдельное общее хранилище с проверками доступа в приложении. Python-сервер **не превращает эти аккаунты в серверную аутентификацию** и не синхронизирует их. Это данные браузера, **не содержимое HTML-файла**. Отправка самого `Domashka_PRO.html` не экспортирует вашу историю, ключи или пароль.

- Приватный режим, очистка данных сайтов, нехватка места, другой браузер/адрес/профиль могут привести к отсутствию или потере данных.
- Для `file://` правила хранения различаются между браузерами. Сохранение при переносе/переименовании файла не гарантируется.
- API-ключи в браузере не зашифрованы родительским паролем. Не вводите их на чужом устройстве и не делитесь своим профилем браузера.
- При облачной обработке задания и фото уходят провайдерам ИИ/OCR. В серверном режиме API-ключ при запросе передаётся также вашему серверу.
- У сервиса нет встроенного общего аккаунта или автоматического облачного резервного копирования.

## 12. Как обновить и не потерять данные

### Локальный HTML

1. Скачайте JSON-копию чатов и отдельно сохраните важные записи дневника.
2. Скачайте новую версию **из актуальной ветки** репозитория, а не старый workspace ZIP.
3. Закройте старые вкладки приложения.
4. Сохраните новый файл под тем же именем **`Domashka_PRO.html`** в прежней папке и откройте тем же браузером.
5. Проверьте версию в интерфейсе/заголовке, историю, выбранную модель и родительский режим. Если требуется, загрузите сохранённый JSON и восстановите настройки вручную.

Совпадение имени/пути помогает, но не является гарантией сохранности `file://`-хранилища. Поэтому резервная копия нужна **до** замены файла. Не изменяйте вручную минифицированный код внутри HTML: разработчик меняет исходники и пересобирает приложение.

### Сайт по HTTPS

После обновления файлов в `main` владелец повторно запускает workflow публикации. Пользователь обновляет страницу; если всё ещё видна старая версия, закрывает старую вкладку и открывает прежний адрес снова. На ПК можно выполнить принудительное обновление (`Ctrl + Shift + R`, на macOS — `Cmd + Shift + R`).

Не очищайте данные сайта первым действием: вместе с кешем можно случайно удалить историю и настройки. Смена домена, протокола или порта создаёт другую область хранения.

<a id="server"></a>
## 14. Серверный запуск для опытных пользователей

**Для обычного использования готового HTML этот раздел не нужен.** Python API может пригодиться для серверных запросов к провайдерам и дополнительных вычислений. Сервер рассчитан на локальную/доверенную среду, а не на публичный многопользовательский сервис.

### Windows

Установите Node.js 20+ и Python 3.11+ с доступом к командам `npm` и `py`. Скачайте исходники актуальной ветки, распакуйте их и откройте терминал в корневой папке проекта:

```powershell
npm ci
py -3 -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
npm run build
.venv\Scripts\python build_standalone.py
.venv\Scripts\python server.py
```

Если PowerShell блокирует `npm.ps1`, можно выполнить команды npm в обычной командной строке Windows либо использовать `npm.cmd`; менять общую политику безопасности системы не требуется.

### macOS / Linux

Установите Node.js 20+ и Python 3.11+, откройте терминал в корне исходников:

```bash
npm ci
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
npm run build:standalone
.venv/bin/python server.py
```

Оставьте терминал запущенным и откройте **`http://localhost:8000`** на этом компьютере. Остановка — `Ctrl + C`. Если порт 8000 занят, остановите другой экземпляр или задайте свободный порт через переменную `PORT` перед запуском.

Для разработки можно дополнительно запустить `npm run dev`: интерфейс будет на `http://localhost:5173`, а `/api` проксируется к Python на порту 8000. Это режим разработки, не обязательный шаг для готового приложения.

### Телефон в той же домашней сети

Сервер слушает сетевые интерфейсы компьютера. При разрешении брандмауэра **только для доверенной частной сети** телефон может открыть `http://ЛОКАЛЬНЫЙ_IP_КОМПЬЮТЕРА:8000`. Например, если адрес компьютера действительно `192.168.1.25`, ссылка будет `http://192.168.1.25:8000`.

- Компьютер должен быть включён, сервер запущен, оба устройства — в одной доступной сети.
- `localhost:8000` на телефоне не ведёт на компьютер.
- На таком HTTP-адресе могут не работать Web Crypto/родительский пароль, микрофон и другие защищённые функции; прямой захват камеры на iPhone отключён. Для обычного использования с телефона предпочтительнее HTTPS-вариант.
- Не открывайте этот Python API в публичный интернет и не настраивайте проброс порта роутера без авторизации, HTTPS, квот и дополнительной защиты.

### Для разработчика: актуальный скачиваемый файл

После изменения исходников или версии выполните `npm run build:standalone` (на Windows при отсутствии команды `python3` — `npm run build`, затем `python build_standalone.py`) и включите обновлённый `Domashka_PRO.html` в тот же коммит. Проверка **Tests and standalone build** повторяет сборку и обнаруживает рассинхронизацию. `static/`, зависимости, пользовательские данные и переносимый ZIP в Git не добавляются.
